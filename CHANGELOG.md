# Changelog

## Unreleased

This release is 1.0.0. The release of 2026-11-04, first published as 1.0.0, is now 1.0.0-preview, a pre-release. The toolbox of both reports version 1.0.0.

### Added

- Homoclinic curves: `phasecont.continuation(..., Type = "HOM")` follows the curve of orbits homoclinic to a saddle in two parameters, starting from a point of long period on an LC branch, and labels its codim-2 points. The inclination flips IFS and IFU are checked only with `InclinationFlips = true`, because they cost an adjoint solve at every point.
- Codim-2 points on curves of cycles: LPPD, LPNS, CPC and R1 on LPC curves, LPPD, PDNS, GPD and R2 on PD curves, and R1 to R4, LPNS, PDNS and CH on NS curves.
- Delay models. A model that calls `delay(x, tau)` runs in `continuation`:
  - equilibria in one parameter, with the roots of the characteristic equation (`Roots`) and LP, BP and H labels;
  - Hopf curves in two parameters, with BT, ZH and HH labels, GH with `Lyapunov = true`, and normal form coefficients at ZH and HH points with `Coefficients = true`;
  - cycles from a Hopf point, with Floquet multipliers (`Floquet = true`), LPC, PD and NS labels, BPC with `Detect = "BPC"`, and a switch onto the other branch at a BPC point (`Switch = "BPC1"`).
- Limit cycles from a simulation: `phasecont.continuation(m, tr, Type = "LC", ...)` starts an LC run from a Trajectory `tr` or from a struct with fields t, x and p. The start is the last period of the orbit. `Period = T` gives the period; without it the period is the time since the latest close return of the orbit to its last point, and the warning `phasecont:continuation:detectedPeriod` names it and the closest return. When a later return was rejected as too far, the period is not clear (an orbit that has not settled, or a cycle that goes round twice), and the run stops with `phasecont:model:badStart`, giving both candidate periods to pass as `Period`. Near a period doubling with a very small split the detected period can still be half the true one, so pass `Period` when you know it. A model that uses t, an orbit that ends at an equilibrium and an orbit with no return are refused with `phasecont:model:badStart`.
- User functions accept formal parameters named arg1 to arg9, bound by name as in XPPAUT: `f(arg2,arg1)=arg1-arg2` called as `f(5,3)` gives -2. A declared argK no longer raises ODE0040, and a declared argK beyond the function's parameter count no longer raises ODE0050. Declaring argK as a parameter, state, aux quantity or any other name is still an error. An argK that the function does not declare still reads argument K, and now gives warning ODE0078, because XPPAUT 8.2.2 stops on it.
- The `only` line of a `.ode` file now loads. `Trajectory.Output` is a table of the listed columns in the order of the list, with `t`, states and aux quantities by name, and `X` still holds every state. A name that is a parameter, a fixed quantity, an unknown name or a repeat is dropped with the warning ODE0077, as XPPAUT 8.2.2 drops it, and ODE0033 is no longer issued. When the list names an aux quantity, `simulate` asks the engine for the aux values at every row, and only the listed ones are kept. A Trajectory from a session saved before this change has no aux values, so its `Output` raises `phasecont:simulate:noAuxColumns` when the list names an aux quantity. `continuation` ignores the list and says so with the warning `phasecont:continuation:onlyIgnored`. The problem JSON of an IVP or ITER run takes the optional key `"aux": true`, which appends the values of every aux quantity to each row after the state, and the `stride` of the run status counts them. `model_info` lists the kept names under `"only"`.
- Mesh adaptation of cycles with the `MeshAdapt` option. It is 3 for ODE cycles and 0 for delay cycles unless you pass it.
- Ensembles: `phasecont.ensemble` integrates many parameter sets and initial states at once on the CPU or on a GPU through CUDA, OpenCL or Metal. `Precision`, the time span and the tolerances (or `Dt`) have no default, single-precision results are labeled as such, and `refine` recomputes chosen members in double precision. `phasecont.gpuDevices` lists the devices and `phasecont.gpuSelfTest` checks one of them.
- Models without a `.ode` file: `Model.fromEquations`, `Model.fromTable`, `Model.fromFunction` and `Model.fromFile`, which also reads SBML. The model editor app is `phasecont.app.ModelEditor`.
- LaTeX output: `phasecont.latex.pgfplots`, `phasecont.latex.figureFromBranch`, `phasecont.latex.specialTable` and `phasecont.latex.build`, which runs `latexmk`. `build` has no time limit unless you pass `Timeout`. The LaTeX editor app is `phasecont.app.LatexStudio`.
- Iteration of maps: `simulate(m, x0, [n0 n1])` on a map iterates it from n0 to n1, and `plot` draws the iterates as dots. `Model.IsMap` tells a map from an ODE. Sessions save and replay these runs.
- Fixed points of maps: `equilibrium` on a map solves F(x) = x and returns the multipliers in `Eigenvalues`, and `continuation` with Type `"EP"` follows the fixed points in one parameter with LP, BP, PD and NS labels and their normal form coefficients. On a map, `Tests` has the four columns `[LP BP PD NS]`, `Detect` takes a subset of `["LP" "BP" "PD" "NS"]`, `Stable` is true where every multiplier has modulus below 1, and an NS point has its angle in `Data.values.theta`. Sessions save and replay these runs.
- Curves of fixed points of maps: `continuation` with Type `"LP"`, `"PD"` or `"NS"` and two free parameters follows the fixed points of a map with a multiplier 1, a multiplier -1 or a pair of multipliers on the unit circle. The Branch has `U` the fixed point, `Alpha` the two parameters and `Eigenvalues` the multipliers, an NS curve has `Kappa`, and `Bounds` bound the second free parameter. The curves label LPPD, LPNS, CP and R1 on LP curves; LPPD, PDNS, GPD and R2 on PD curves; and R1 to R4, LPNS, PDNS, NSNS and CH on NS curves, with NaN `Data.coefficient`. Sessions save and replay these runs.
- Period-k points of maps: `Iterate = k` on `equilibrium` and `continuation` works with the k-th iterate of the map, and `Branch.Iterate` holds k. `Switch = "PD1"` on an EP run of a map returns the branch at iterate k and the branch at iterate 2k that starts at the first PD point of the first branch, and a run with Type `"EP"` from a PD point at iterate k starts the branch at iterate 2k. LP, PD and NS curves run at the iterate of the special point they start from. Sessions save and replay runs at any iterate.
- Maps in the phase-plane app: on a map with two or more variables, `phasecont.app.PhasePlane` iterates from a click (the T field is labeled N), marks fixed points as stable or unstable from their multipliers and draws the curves where the map leaves a variable unchanged as its nullclines. On a map with one variable that does not use `t`, it opens a cobweb view. `phasecont.cobweb(m, x0, N)` draws the cobweb of a map with one variable in any axes. `phasecont:app:mapModel` now means that an action, such as a backward run or the direction field, does not apply to a map.
- Ensembles of maps: `phasecont.ensemble` iterates a map on the CPU and on CUDA, OpenCL and Metal, with `t` inside the model the iterate index. `TSPAN` holds whole numbers, `Precision` is the only required option, and `Dt`, `Rtol`, `Atol`, `Hmax` and `MaxSteps` raise `phasecont:ensemble:mapOption`. `Job.Method` is `"iter"`, and `refine` iterates again on the CPU in double precision. The self-test of `pc-cli gpu selftest` has an `iterate` tier, and its determinism and bit-exactness tiers also run the Henon map.
- `FastMath = true` on `phasecont.ensemble` lets the CUDA compiler fuse multiply-adds in double precision, which cut a van der Pol ensemble of 100000 members from 57.5 to 38.9 ms (RK4) and from 157.5 to 107.9 ms (Dormand-Prince) on an RTX 5060 Laptop GPU, timed through MATLAB. It raises the warning `phasecont:ensemble:fastMath` on every run, the results are not bit-reproducible, `R.Label.Math` is `"fma"`, and `refine` runs without it. Any other backend or precision raises `phasecont:ensemble:fastMathBackend`. The CLI and C ABI job JSON takes the same tier as the optional key `"math": "exact" | "fma"`, the result label carries `math`, and the CUDA double run of `pc-cli gpu selftest` reports the largest difference between the two tiers under `fma` without failing on it. On CUDA in double, `phasecont.gpuSelfTest` reports the same comparison in its `FastMath` field (`MaxDifference`, `StatusDiffer`), which does not count in `Pass`.
- Data fitting: `phasecont.fit` fits chosen parameters of an ODE model to trajectory data with the Levenberg-Marquardt method, with one `ensemble` call per iteration in double precision on the CPU, and returns a `phasecont.FitResult` with the estimate, the residual, the Jacobian and the history of the iterations. The difference step, the damping and the stopping rules have no default.
- `Point.Stable`: an `"EP"` Point from `equilibrium` or a session says whether the equilibrium or the fixed point is stable, from its eigenvalues or multipliers. It is empty at a special point such as LP, PD or H, where the linear test decides nothing. It is not stored, so session files do not change.
- `simulate(..., Thin = tol)` keeps fewer rows of an ODE run. A row is dropped only when the straight line in t between the rows kept on either side gives every state and stored aux value within tol times the range of that column, so `tol` is a fraction between 0 and 1. The first and last rows are kept, and so is every row with a NaN or Inf value together with the rows next to it. Kept rows are the unthinned rows bit for bit. On the Hopf normal form over [0 40], a Lorenz run over [0 20] and a stiff scalar model over [0 6], `Thin = 1e-2` kept 25%, 11% and 0.5% of the rows, and `Thin = 1e-3` kept 88%, 35% and 1.6%. `TR.Thin` holds the tolerance, sessions save and replay it, and a map raises `phasecont:simulate:mapOption`. An LC start from a thinned Trajectory integrates the run again without `Thin`, after the warning `phasecont:continuation:thinRerun`, and a thinned Trajectory with no record of its run is refused with `phasecont:model:badStart`. The IVP problem JSON takes the same rule as the optional key `"thin"`, which the other run types refuse.
- `plot` on a Trajectory or a Branch draws a long line with fewer vertices. On a 2-D axes, when a line has more than 4 times as many rows as the axes is wide in pixels, it draws a row only when it falls in a different cell of 0.35 by 0.35 pixels from the row before it, plus the ends, the rows of the smallest and largest x and y, and every row with a NaN or Inf value or, on a log axis, a value of 0 or less. The rule runs again after every zoom, pan, resize or change of scale, so the drawn line stays within half a pixel of the full one, and a 3-D view draws every row. Every drawn vertex is a data row bit for bit, and `UserData.PhaseContRows` of each line holds the indices of the drawn rows into `T` or `Alpha`. The dots of a map are always drawn exact. A run of 10^6 rows of y = t^2, plotted in a 700 by 500 pixel figure whose axes are 542.5 by 407.5 pixels, draws 2714 vertices. Exported vector figures and `print` carry the vertices on screen at the time of export.
- A language server (`pc-lsp`) and a VS Code extension for `.ode` files. The extension is built as a `.vsix` file and is not on the Marketplace. It needs VS Code 1.146 or newer.
- A line that has text after a backslash loads as XPPAUT 8.2.2 loads it, with the text dropped and the next line joined, and gets the warning ODE0075, which quotes the dropped text. A `#` comment line or an active comment (a line that starts with `"`) that ends in a backslash swallows the next line, as in XPPAUT, and gets the warning ODE0076, except on line 1 of the main file. An active comment on line 1 that ends in a backslash no longer joins line 2. The language server offers two quick fixes for each warning. The `.ode` writer cuts a comment before its first backslash.

### Security

- Windows: the GPU backends never load a library from MATLAB's current folder. cudarc and the OpenCL loader open `cuda.dll`, `nvrtc.dll`, `OpenCL.dll` and similar names by bare name, and Windows searches the current folder for those, so before this change a file with one of those names in the current folder ran inside MATLAB at the first call of `phasecont.gpuDevices`, `phasecont.gpuSelfTest` or `phasecont.ensemble`. The first loads now skip the current folder, the CUDA driver and the OpenCL loader come from the Windows system folder, and the NVRTC builtins library is loaded by path from the folder of the NVRTC in use. The folders on `PATH` are still searched, as for any Windows program. Release 1.0.0-preview has no GPU backend and is not affected.
- Windows: `phasecont.latex.build` and the LaTeX editor app never run a `latexmk` from MATLAB's current folder. A bare program name went to cmd.exe, which looks in the current folder before `PATH`, so a `latexmk.bat` in a downloaded folder ran on the first build. The name is now looked up in the `PATH` folders only and runs by its full path. Release 1.0.0-preview has no LaTeX build and is not affected.
- `Session.load` and `phasecont.session.replay` no longer build an AOT library because a session file records `"aot"`. Before this change, loading such a file ran `mex` on C code generated from the model source in the file. The C text comes from our own code generator, but a session file from someone else should not start a compiler on its own. Such a file now loads with the evaluator that `phasecont.config("Codegen")` names (`"jit"` unless you changed it), and the `Evaluator` option still picks one. A file that records any evaluator other than `"jit"`, `"fallback"` or `"aot"` raises `phasecont:session:badFile`. Release 1.0.0-preview is affected.
- Loading a MAT file that holds a `phasecont.Model` saved with `Evaluator` `"aot"` no longer builds an AOT library. Before this change, `load` ran `mex` on C code generated from the model source in the file, the same route the session fix above closed for session files. The model now loads with the evaluator that `phasecont.config("Codegen")` names, so a saved `"jit"` or `"fallback"` model loads as before and a saved `"aot"` model loads on the JIT unless `Codegen` is `"aot"`. Release 1.0.0-preview is affected.

### Changed

- IVP and ITER runs keep their rows in one flat buffer instead of one continuation point per step, which cuts the memory of a long `simulate` run and drops the second copy held while the run goes. The rows, their bits and the row layout do not change. The point records that `pc-cli cont` writes for an IVP or ITER run no longer have an `h` key, since the store keeps no step size.
- `pc-cli session replay` refuses a session file whose `model.evaluator` is not `"jit"`, `"fallback"` or `"aot"` and exits 2, as `phasecont.session.replay` already did with `phasecont:session:badFile`. Before, any other value replayed on the JIT without a message.
- On macOS, `ensemble` with `Backend = "auto"` tries Metal before OpenCL, since Apple deprecated OpenCL in favor of Metal. Windows and Linux keep the order CUDA, OpenCL, Metal, CPU. Pass `Backend = "opencl"` to keep OpenCL on a Mac.
- The release ships one package per platform, `PhaseCont-<version>-win64.mltbx`, `PhaseCont-<version>-glnxa64.mltbx` and `PhaseCont-<version>-maca64.mltbx`, next to `PhaseCont-<version>.mltbx`, which holds all three platforms as before. All four use the same toolbox identifier, so any of them replaces an installed PhaseCont. A local `buildtool package` now writes `build/PhaseCont-<version>-<arch>.mltbx`.
- Single-precision CPU ensembles run a compiled right-hand side, as double precision already did. `vdp-rk4` at 100000 members runs about 1.9 times faster, with the same bits as before. Models that use tables or erf, erfc, lgamma, the Bessel functions or polygamma still run on the interpreter in single precision.
- `simulate` warns once per model with `phasecont:simulate:ignoredOption` and names the `@` options of the model, such as `meth` and `dt`, since it uses none of them. The results do not change. The warning comes after the run, so a run that fails gives no warning.
- `simulate` iterates a map, and `equilibrium` and `continuation` with Types `"EP"`, `"LP"`, `"PD"` and `"NS"` compute its fixed points, their multipliers and the curves of its LP, PD and NS points. In 1.0.0-preview they treated the right-hand side of a map as an ODE and gave wrong results. Types `"H"`, `"LC"`, `"LPC"` and `"HOM"` on a map now raise a `phasecont:` error. `phasecont.app.PhasePlane` shows a map instead of a vector field (see Added). `Model.rhs` still evaluates the right-hand side.
- A file of `x'=...` lines with `@ meth=discrete` (any `meth` value that starts with `d`) is now a map, as in XPPAUT, so it runs as a map in every call above. In 1.0.0-preview it was integrated as an ODE, and `ensemble` integrated it too.
- `continuation`, `simulate` and session replay check for the result more often in the first few milliseconds, so short runs return in about 5 ms instead of about 50 ms. The results do not change.
- Rows of LPC, PD and NS curves have more `Tests` columns, one per new codim-2 test. Code that reads these columns by position needs the new widths.
- `shift` and `del_shft` are now refused with a message that names the function, instead of an error about the number of arguments.
- The VS Code extension uses `vscode-languageclient` 11. `phasecont.trace.server` now logs only while the log level of the PhaseCont output channel is Trace (`Developer: Set Log Level...`), and at Trace its `off` value logs the messages, the same as `messages`.
- The `.ode` reader follows XPPAUT 8.2.2 in seven more places:
  - any first word that starts with `n` declares a constant, as `number` does;
  - any first word that starts with `so` is read as `solv`, which is still refused with the DAE message ODE0030;
  - a backslash followed by blanks at the end of a line continues the line, as a bare backslash already did;
  - `name[n]` with a whole number n is read as `name<n>`, in formulas and in declarations, so `k[03]` is `k3`;
  - an `aux` may have the name of a fixed quantity or a parameter. The aux column keeps its own formula and every other reader of the name gets the fixed quantity or the parameter. A second aux of that name, or an aux with the name of a state, is still ODE0041;
  - on a `global` line, `arret` and `out_put` are read as event actions. A `global` model is still refused as simulation only;
  - `nout` and `njmpx` in an `@` line are read as `njmp`, and the last of the three names wins.
- `pc-cli check-derivs` reports an entry too large to build as SKIP instead of failing on it. The finite-difference rows use Richardson extrapolation of the central differences and allow for the rounding of the model values, so a model with a tiny derivative next to a large value (for example `x' = -x + y^q/(y^q + 1)` with `q` near 4) no longer fails through rounding. They leave out sample points only where the model value is not finite in the fallback and the DAG gives the same value there. A point where the DAG is not finite and the fallback is, or where the two differ in another way, is compared and fails. Each row prints how many points and values it compared, and a row that compared no value fails.

### Fixed

- Models built with the AOT evaluator run LPC, PD and NS curves. The AOT library had no `F_up` entry, which those curves use, so they stopped with "AOT library has no entry d_up".
- Maps built with the AOT evaluator run LP, PD and NS curves at `Iterate` 2 or more, and EP branches there refine their LP and BP points. The k-th iterate asks for the directional derivative of the whole map, which the AOT library did not hold, so those curves stopped with "AOT library has no entry d_f" and EP branches warned "could not refine LP near point ..." and left the point unrefined. Adding the entry changes the tag of every AOT library, so a cached library is built again on first use.
- Jacobians and directional derivatives no longer give NaN at a point where a clamped term such as `sqrt(max(a-x,0))` or `exp(-1/max(a-x,0))` sits at its clamp. A tangent that is zero at run time now adds +0 even where the partial derivative is infinite or NaN, so the derivative of `sqrt(u^2)` at u = 0 is 0. Every stored zero derivative is +0 in every evaluator (the DAG, the interpreter, the JIT and the AOT C). Product terms and chain terms of a call whose other factor or argument can be non-finite are guarded the same way, for example in `exp(-c*(1/max(a-x-10,0)))` and `exp(-(1/max(a-x-10,0))^2)`. Elsewhere the only change is the sign of some zero entries (-0 against +0). The ensemble benchmark results do not change.

### Compatibility

- If you installed 1.0.0-preview, uninstall it in the Add-On Manager before installing 1.0.0. Both report version 1.0.0 with the same toolbox identifier, and an install of one over the other has not been tested.
- Session files saved by 1.0.0-preview still load. Their LPC, PD and NS rows get NaN in the new test columns. Replaying such a run reports that the row layout changed.
- A session saved by 1.0.0-preview with a run on a map loads with its stored rows, which are wrong. An EP branch of a map from such a file gets NaN in its PD and NS columns, since 1.0.0-preview stored an H test there. Replaying any of these runs gives `Pass = false`, since 1.0.0-preview treated the map as an ODE. A run that the engine refuses, such as an integration of a map or an EP branch that asks for the H test, also warns with `phasecont:session:runFailed`.
- The engine library and the MEX gateway must come from the same release. A new gateway refuses an old library, which can happen only after a partial upgrade.
- As in 1.0.0-preview, close every MATLAB session that used PhaseCont before you install a new version, or the install fails with "Permission denied".

### Known limits

- Maps (`x(t+1)=...`, or `x'=...` with `@ meth=discrete`) run only in `simulate`, `equilibrium`, `continuation` with Types `"EP"`, `"LP"`, `"PD"` and `"NS"`, `PhasePlane`, `cobweb` and `ensemble`. Types `"H"`, `"LC"`, `"LPC"` and `"HOM"` refuse them, so a cycle of a map is followed as a fixed point of its k-th iterate with `Iterate`. `PhasePlane` iterates a map forward only. The codim-2 points of map curves have no normal form coefficients, and the least period of a period-k point is not checked. `fit` refuses them with `phasecont:fit:mapModel`.
- Three bounds in the continuation of map curves have no published source: a start must lie within 10^-6 of its curve, a CH sign change counts only above 10^-8, and the CH test divides by c1 and checks only for an exact zero. The `Switch = "PD1"` option and a start at a PD point of a map, and `Switch = "BP1"` on a map or an ODE, refuse a point whose two smallest singular values lie within a factor of 10^3 of each other as not simple, and that factor has no published source either.
- Delay models run only in `continuation`. `simulate`, `equilibrium` and `ensemble` refuse them.
- The `.ode` reader refuses noise, `global`, differential-algebraic and Volterra equations, boundary value problems, `sum`, `shift`, `special`, `export`, tables read from a file and `#include`. The README lists them.
- `simulate` integrates only with the Dormand-Prince 5(4) pair.
- The classification of Hopf-Hopf points into unfolding cases is not yet checked against a published table, and help marks the case letters as unconfirmed.
- GPU ensembles have run on an NVIDIA RTX 5060 Laptop GPU (CUDA and OpenCL, single and double precision) and an Intel Arc 140T (OpenCL, single and double precision). Metal has run only on the virtual GPU of GitHub's hosted macOS runners, in single precision, never on Apple hardware. No AMD device has run.
