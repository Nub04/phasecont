# PhaseCont technical spec

This file is the source of truth for what the engine computes and how each phase is accepted. Where a formula here conflicts with a cited reference, the reference wins: stop, note the conflict in `docs/STATUS.md`, and ask.

## 1. Data flow

```
.ode text
  -> pc-ode      parse, validate, diagnostics, AST
  -> pc-ir       expression DAG, constant folding, CSE, symbolic derivatives
  -> pc-jit      Cranelift native functions (default)
     pc-codegen  C (optional AOT), CUDA C, OpenCL C, MSL, LaTeX, MATLAB reference
  -> pc-engine   continuation, test functions, normal forms, limit cycles
  -> pc-ffi      C ABI, handle registry, panic barrier
  -> mex gateway
  -> toolbox/+phasecont  MATLAB API, apps, plots, sessions
```

`pc-cli` drives the same Rust crates without MATLAB, so the engine can be tested and benchmarked on CI runners that have no MATLAB license.

## 2. `.ode` support for v1

The rules below were checked against the XPPAUT manuals (v5.0, v5.41, v8 notes) and measured with XPPAUT 8.0 on our own probe files (`references/xpp-probes/`). The full language reference, with the precedence table, the builtin semantics table and the diagnostic codes, is `crates/pc-ode/docs/language.md`.

Parsing rules:
- **Keywords:** only the first letter is significant for the nine declarations `markov`, `parameter`, `wiener`, `table`, `aux`, `init`, `bndry`, `global` and `done` (`p`, `par` and `pzz` all declare parameters). Other keywords (`number`, `set`, `options`, `only`, `special`, `solv`, `export`, `volt`, `hom_bcs`) need the full word. A first word is a keyword only when a blank or the end of the line follows it and the next non-blank character is not `=`, so `p=3` and `p = 3` define a fixed quantity named `p`.
- **Case:** the language is case-insensitive.
- **Names:** XPPAUT 8.0 accepts a declared name longer than 10 characters but stops with an error where the name is used in a formula. A longer name gives a portability warning, not an error.
- **Line continuation:** a backslash at the end of a line continues it.
- **Order:** names may be used before their declaration, except fixed quantities: XPPAUT evaluates them in file order, so a fixed quantity that uses one defined on a later line is an error.
- **Spaces around `=`:** accepted in `par`, `number` and `init` lists and in formulas. In `@` lists XPPAUT 8.0 accepts the line but ignores the option, so PhaseCont gives a warning with a fix-it.
- **Declared values:** `par`, `number`, `init` and `x(0)=` values are signed numeric literals (XPPAUT reads only a leading number); inside an array template a value may also be a bare index form (`x[j](0)=[j]`). A repeated `par` is an error.
- **Comments:** `#` at the start of a line. A trailing `#` comment is accepted after `par`, `number` and `@` lists, where XPPAUT 8.0 ignores it, and is an error elsewhere: XPPAUT 8.0 rejects it after formulas and `init` lists, and PhaseCont also rejects it after the statements that were not measured.
- **Arrays:** range lines (`x[1..10]'=-x[j]`) and `%[1..n]` ... `%` blocks are expanded during loading.
- **Old-style files**, whose first line starts with a digit, are an error.

| Construct | Example | v1 status |

**Expressions.**
- Operators: `+ - * /`, `^` and `**` for powers, prefix `-` and `not`, comparisons `< > <= >= ==`, and `&` and `|`. XPPAUT's precedence differs from C: `&` binds like `*`, `|` like `+`, comparisons bind tighter than arithmetic, and `^` is left-associative. PhaseCont follows XPPAUT and warns where the reading is surprising. The measured table is in `language.md`.
- A number followed directly by a name or `(` (`2v`) multiplies, with a portability warning, since XPPAUT 8.0 rejects it.
- Built-in functions: `sin cos tan asin acos atan atan2 sinh cosh tanh exp ln log log10 sqrt abs heav sign mod min max flr ceil erf erfc lgamma besselj bessely`, and `if(c)then(a)else(b)`. `ceil` gets a portability warning.
- `ran`, `normal` and `poisson` make a model simulation-only, as do `markov`, `wiener` and `global`.
- The exact meaning of each function (for example that `log` is natural and `atan2(y,x)` uses C's order), with its source, is in the semantics table in `language.md`. Division follows IEEE (`1/0` is inf, `0/0` is NaN), unlike XPPAUT's guarded division. `mod(x,y)` is `r = fmod(x,y)`, plus `y` when `r < 0`. `if` evaluates both branches and selects one with the test `c != 0`. Constant folding in `pc-ir` drops NaN and inf from terms it removes (`x*0` is 0), and it can change the sign of a zero (`x*0` is `+0`, so `atan2(x*0,-1)` at `x = -1` is `+pi` in the DAG and `-pi` in the interpreter); `language.md` lists the rules.

**Non-smooth models.**
- Any of `heav sign abs mod flr ceil min max if`, a comparison (`< <= > >= ==`), `&`, `|`, `not`, or a table, marks a model as non-smooth.
- Equilibrium continuation is allowed, with a warning, as long as no switching surface is crossed.
- Derivatives use one-sided rules and the result is flagged.

**Diagnostics.**
- Each diagnostic has a code (`ODE0001`...), a line and column, a message, and an optional fix-it.
- The same diagnostics feed the MATLAB import report and, later, the VS Code language server.

**Round trip.** For every model, `parse(write(parse(s)))` must equal `parse(s)` (checked with `proptest`).

## 3. IR and derivatives (pc-ir)

**DAG structure.**
- A hash-consed DAG of `f64` operations, with constant folding and common subexpression elimination. Folding happens when a node is built, so hash-consing gives CSE for free. The algebraic rules and their effect on NaN are in `language.md`; there is no reassociation.
- Fixed quantities and user functions are inlined. Inline formula tables are tabulated when the model is lowered and read with linear interpolation.
- Time `t` is a hidden parameter slot `p[n_p]`, so every entry keeps the same signature. The IR records whether the model is autonomous.
- Every transcendental goes through one table of shims in `pc-ir`, backed by the `libm` crate. The interpreter, the DAG evaluator, the JIT and the AOT code all call the same functions.
- `pc-ir` refuses simulation-only models, unsupported statements and any form of `delay` outside Section 8d with an error that points at the source. `build` refuses a model that uses `delay` at all; only `build_dde` accepts it. A DAG over 1,000,000 nodes is an error.

**Derivatives produced by symbolic forward differentiation on the DAG.** Each one is a new DAG that goes through CSE again:
- $f(u,\alpha)$
- the Jacobian $A = f_u$ ($n \times n$)
- the parameter Jacobian $f_\alpha$ ($n \times n_p$)
- the multilinear forms $B(v_1,v_2) = D^2 f(u)[v_1,v_2]$ and $C(v_1,v_2,v_3) = D^3 f(u)[v_1,v_2,v_3]$
- directional derivatives up to order 5, for normal forms
- the mixed parameter derivatives needed by branch switching

$A$ and $f_\alpha$ come from first-order symbolic differentiation. Orders 2 to 5 use a multilinear (hyper-dual) expansion on the DAG: each node gets one component per subset of the $k$ direction slots, a product splits over subsets, and a call $g(w)$ uses Faà di Bruno's formula over set partitions, with $g^{(m)}$ from repeated symbolic differentiation. The result is exact, with no polarization. Directions live in the extended space $(u,\alpha)$ of length $n+n_p$, so one mechanism gives $B$, $C$, the order 4 and 5 forms, and mixed forms such as $A_\alpha v = D^2 f[(v,0),(0,e_j)]$. Each slot is marked as $u$ only, $\alpha$ only or full, so zero blocks fold away. Non-smooth builtins use the derivative of the active branch (`language.md` lists the rules).

**Complex directions.** Directional derivatives must accept complex direction vectors, because $q$ and $p$ in the normal forms are complex. PhaseCont splits each complex direction into its real and imaginary parts and uses multilinearity, so an order $k$ form takes at most $2^k$ real evaluations. There is no complex-valued entry point.

**Validation uses two independent evaluators:**
1. A tree-walking dual-number interpreter on the AST, using nested dual numbers up to depth 5. Its results must match the generated derivatives to within 4 ulp per entry, or $10^{-13}$ relative error. Let $a$ be the value from the DAG (or the JIT) and $b$ the value from the interpreter, and let $s$ be the largest magnitude in that output vector. An entry passes when any of these holds:
   - $a$ and $b$ are both NaN, or $a = b$;
   - $|a-b| \le 4\,\mathrm{ulp}(\max(|a|,|b|))$;
   - $|a-b| \le 10^{-13} s$;
   - $|a-b| \le 10^{-15}$, because values near zero carry rounding from larger intermediate terms;
   - $|a-b| \le 8\,\varepsilon\,E_i$, where $\varepsilon$ is the machine epsilon and $E_i$ is the running error bound of output $i$ of the DAG evaluation. A NaN or infinite $E_i$ adds no pass.

   $E$ is computed beside the value by Wilkinson's running error analysis (Higham, *Accuracy and Stability of Numerical Algorithms*, 2nd ed., 2002, section 3.3), so that the rounding error of the computed value is at most $uE$ to first order, with $u = \varepsilon/2$. Leaves are exact ($E = 0$) and every rounded operation adds $|r|$ for its result $r$: `Add` and `Sub` give $E_a + E_b + |r|$, `Mul` gives $|a|E_b + |b|E_a + |r|$ and `Div` gives $(E_a + |r|E_b)/|b| + |r|$. Input errors pass through the exact first derivatives (the partials of the dual-number rules), so `Call1` gives $|f'(a)|E_a + 2|r|$ and `Call2` gives $|\partial_a f|E_a + |\partial_b f|E_b + 2|r|$. `PowI` with exponent $n$ gives $|n||r|E_a/|a| + (|n|-1)|r|$, because the roundings of binary powering compound by the `Mul` rule, plus $|r|$ for the reciprocal when $n < 0$. `Select` takes the bound of the branch taken, a table gives $|\mathrm{slope}|E_a + |r|$, `TableSlope` gives 0, and comparisons and logic give 0. An exact input ($E_a = 0$) adds nothing through a partial that is infinite or NaN, and any other non-finite partial makes $E$ non-finite.

   The factor 8 is 16 times the first-order bound $uE$ of one evaluator ($8\varepsilon = 16u$). That leaves room for the rounding of the interpreter, which $E$ does not model. The condition covers cancellation in high-order directional derivatives, where the terms are far larger than $s$ and $10^{-13}s$ sits below their rounding noise. $E$ is a first-order bound: `floor`, `ceil`, `heav`, `sign`, comparisons and `Select` contribute nothing for a jump, so a rounding difference that crosses a jump on a non-smooth model can still fail a row.
2. Central finite differences on random inputs, with relative error at most $10^{-6}$ for $A$ and at most $10^{-4}$ for $B$ and $C$, measured against the same scale $s$.

## 4. JIT and AOT (pc-jit, pc-codegen)

**Entry points.** Lower each needed DAG to Cranelift IR as an `extern "C"` function. A typical signature is `fn(x: *const f64, p: *const f64, out: *mut f64)`. Directional entries take extra vector pointers. Matrix outputs such as the Jacobian are written column major.

**Code generation flags.** Set `is_pic` only on x86_64 and set `use_colocated_libcalls` to false, as `JITBuilder::new` does. Set `enable_probestack` to true and `probestack_strategy` to `inline`. Cranelift leaves stack probes off by default, Windows needs them for frames over 4096 bytes, and the default `outline` strategy calls `__cranelift_probestack`, which `pckern` does not provide.

**Transcendentals.** Call the `extern "C"` shims of `pc-ir` (section 3), which wrap the `libm` crate, not the `f64` methods of std. Register every shim with `JITBuilder::symbol`. Shim bodies must not panic: a panic that leaves an `extern "C"` function aborts the process, JIT frames have no unwind information, and the panic barrier sits outside the JIT call.

**Ownership.** Each compiled model owns its `JITModule`. Dropping a `JITModule` leaves its code pages mapped, so the model handle calls `JITModule::free_memory` when it is freed and on every error path after `JITModule::new`, and only when no thread can still call the compiled functions.

**Equivalence.** JIT output for $f$ must match the dual-number interpreter to within 4 ulp. For derivatives the two use different algorithms, so they are compared with the tolerance of section 3, including the $8\,\varepsilon\,E_i$ condition with $E_i$ taken from the DAG evaluation of the same entry. JIT output must also match a Rust evaluator of the same DAG exactly (0 ulp), since Cranelift emits no fused multiply-add unless asked.

**AOT path.** `pc-codegen` emits C with the same signatures. The C does not call the C library: it declares `const pc_math_t *pc_math` and exports `pc_aot_init(const pc_math_t *)`, and the loader passes the `pc-ir` shim table, so AOT and JIT call the same math functions. It is compiled through `mex` when a compiler exists and selected with `phasecont.config("Codegen","aot")`. AOT output must match JIT output to within 4 ulp. Compile AOT code with floating-point contraction turned off, as the spike's gcc build does with `-ffp-contract=off`, and store the compiler, its version and its flags with every benchmark or test result that uses AOT code.

In P8a the loader is `Evaluator::Aot` in pc-engine. `libloading` opens the library that `mex` built, and the loader calls `pc_aot_init` with the `pc-ir` shim table before any entry. The library handle is kept for the life of the model. `model_compile` takes the keys `"emit_c":"<dir>"`, which writes the C text into that folder, and `"evaluator":"aot"` with `"aot_lib":"<path>"`, which loads the built library (section 10). On the MATLAB side, `internal.aotBuild` runs `mex` on the emitted C plus a stub `mexFunction`, with contraction off (`/fp:strict` on MSVC, `-ffp-contract=off` elsewhere). It caches the library under `tempdir`, and `Model.AotInfo` stores the compiler, its version and the flags. With no compiler, a failed compile or a blocked load, the model runs on the JIT and PhaseCont warns with a `phasecont:aot:*` identifier. Both paths agree within 4 ulp, so the warning is the only visible change. NaNs compare by class, not by sign.

**macOS arm64.** Confirm that JIT pages can be mapped executable inside the MATLAB process. Phase 0 ran only on Windows and WSL, so Phase 2 runs the Rust side of this check on the macOS runner of section 12, and the part inside MATLAB waits for a MATLAB licensing token for the macOS runner (deferred from Phase 7a, see `docs/STATUS.md`). `cranelift-jit` 0.137.0 accepts `is_pic=true` only on x86_64. Its default `SystemMemoryProvider` maps code pages read-write without `MAP_JIT` and makes them read-execute with `mprotect`, which the hardened runtime allows only with `com.apple.security.cs.allow-unsigned-executable-memory` or `com.apple.security.cs.disable-executable-page-protection`. `codesign -d --entitlements - <matlabroot>/bin/maca64/MATLAB`, where `<matlabroot>` is the folder that `matlabroot` returns, lists the entitlements MATLAB has. Without either entitlement, `pc-jit` needs its own `JITMemoryProvider`, set with `JITBuilder::memory_provider`, that maps pages with `MAP_JIT`, which needs `com.apple.security.cs.allow-jit`, and switches them with `pthread_jit_write_protect_np`. With none of the three, users still need no compiler: models run on an `f64` evaluator in Rust built from the same code as the dual-number interpreter of section 3, and PhaseCont warns that this is slower than compiled code. The AOT path stays the optional speed-up on Macs that have the Xcode Command Line Tools, selected with `phasecont.config("Codegen","aot")`. No Mac user is required to install a compiler.

## 5. Continuation core (pc-engine)

**Notation.** Let $x = (u,\alpha) \in \mathbb{R}^{n+1}$ and $F(x) = f(u,\alpha)$.

**Tangent.** Solve
$$\begin{pmatrix} F_x(x_k) \\ v_{k-1}^\top \end{pmatrix} v_k = \begin{pmatrix} 0 \\ 1 \end{pmatrix}, \qquad v_k \leftarrow \frac{v_k}{\|v_k\|}.$$

**Pseudo-arclength (PALC) step.** Predict $x^{(0)} = x_k + h v_k$, then correct with Newton's method on
$$G(x) = \begin{pmatrix} F(x) \\ v_k^\top (x - x_k) - h \end{pmatrix} = 0.$$

**Convergence and step control.**
- The corrector has converged when $\|\Delta x\|_\infty \le 10^{-10}$ and $\|F\|_\infty \le 10^{-10}$ (both configurable).
- If Newton converges in 3 or fewer iterations, set $h \leftarrow \min(1.3h, h_{\max})$.
- If it fails after 6 iterations (configurable), set $h \leftarrow h/2$ and retry.
- Below $h_{\min}$, stop the branch and report the reason.
- A branch also stops at the maximum step count, at a bound on $\alpha$ (the last step is cut back so that $\alpha$ lands on the bound), when the bordered matrix is singular, and on cancel. Each stop records its reason.

**Starting point.** The `init` values of a model are rarely an equilibrium, so a branch starts with Newton's method on $F(u) = 0$ at fixed parameters, with the same tolerances as the corrector. The first tangent solves the system above with $e_\alpha$ in place of $v_{k-1}$, and its sign is chosen by the requested direction. Models that depend on $t$ are refused, and so are models with a formula table that reads a parameter, since `lower` tabulates it once from the declared values.

**Test functions on equilibrium branches.** $\lambda_i$ are the eigenvalues of $A$.
- **LP:** $\psi_{LP} = v_{k,\alpha}$, the parameter component of the tangent.
- **BP:** $\psi_{BP} = \det \begin{pmatrix} F_x \\ v^\top \end{pmatrix}$, taken from the LU factors of the tangent solve.
- **H:** the zeros of $\prod_{i<j} (\lambda_i + \lambda_j)$, which equals $\det(2A \odot I)$. Let $s_{ij} = (\lambda_i + \lambda_j) / \max(1, |\lambda_i| + |\lambda_j|)$ and let $s_k$ be the factor of smallest modulus. The engine computes
  $$\psi_H = \operatorname{sign}\Big( \prod_{i<j} s_{ij} \Big)\, |s_k|.$$
  It is continuous in $A$, it has the sign of the plain product, and it is 0 exactly where some factor is 0 (two factors vanishing together also give 0). Its modulus is at most 1, so it neither overflows nor underflows to 0 away from a zero, even with many slow modes. For $n = 1$ there are no pairs and $\psi_H = 1$. Near a zero, $\psi_H$ can be nearly flat when another factor is tiny and hardly changes, so the zero search along a step uses the plain product divided by its modulus at point $k$, computed through logarithms.
- $\psi_H$ vanishes at Hopf points and at neutral saddles. At a zero, the pair with the smallest scaled $|\lambda_i + \lambda_j|$ decides: a complex conjugate pair is a Hopf point (`H`), a real pair $\pm\lambda$ is a neutral saddle, labeled `NSA` and not reported as Hopf. (`NS` is Neimark-Sacker.)
- Hopf detection has no limit on $n$. The product costs $O(n^2)$ on the dense eigenvalues, which the engine computes at every point anyway for the $O(n^3)$ eigenvalue step, so it adds a few percent (`docs/STATUS.md` lists timings up to $n = 1000$). Phase 4 kept the dense route. Govaerts' minimally augmented Hopf function needs $\kappa = \omega^2$ as an unknown, so it is not a scalar test function along an equilibrium branch, and no source that gives such a test was confirmed.

**Locating special points.**
1. When a test function changes sign strictly between $x_k$ and $x_{k+1}$, find $s \in (0,1)$ where it vanishes. Each trial point is corrected from $x_k + s h v_k$ on the hyperplane $v_k^\top(x - x_k) = s h$. The iteration is a secant method with a bisection safeguard (Illinois regula falsi), at most 30 iterations.
2. Refine the point by solving its defining system (Section 6) with Newton's method. If that Newton fails, the located point is kept and marked as not refined.
3. Store the point, its eigenvalues and its normal form coefficient on the branch.
4. A branch that starts at a special point (after branch switching) skips detection on its first step.

**Branch storage.** Columns are $u$, $\alpha$, tangent, eigenvalues (or multipliers), test function values, step size and Newton iteration count. Special points carry a label, an index and a struct of extras.

**Background runs.** A continuation runs on a Rust background thread. MATLAB polls for new points with `pc_run_poll` from a `timer`, so plots update live, and `pc_run_cancel` stops the run. Cancel is checked between Newton iterations and between steps. A panic on the background thread is caught on that thread, with its message and source location, and the next `pc_run_poll` reports it as an error.
- A compiled model is not `Send` (it holds code pointers), and the lowered `IrModel` is not `Clone`. A run therefore takes copies of the checked model and its `ModelInfo`, and the worker lowers and compiles them on its own thread.
- `pc-engine` owns the panic hook. It is installed once, stores the message and `file:line:col` of a panic on an engine worker in a thread local, and prints nothing, since stderr is lost inside MATLAB. `pc-ffi` reuses it in Phase 7a.

## 6. Equilibrium bifurcations and normal forms

**Fold (LP).** With $Aq = 0$, $A^\top p = 0$, $p^\top q = 1$ and $\|q\| = 1$, the quadratic coefficient is
$$a = \tfrac{1}{2}\, p^\top B(q,q).$$
The sign of $q$ is chosen so that $p^\top F_\alpha > 0$. The normal form is then $\dot w = \beta + a w^2$ with $\beta$ increasing in $\alpha$ (Kuznetsov, Theorem 3.1), so the sign of $a$ tells on which side of the fold the two equilibria lie. If $p^\top F_\alpha$ is exactly 0, the fold is not generic and $q$ keeps the sign of the null vector solve.

**Minimally augmented LP curve** (Govaerts 2000). Solve
$$\begin{pmatrix} A & w_{\text{bor}} \\ v_{\text{bor}}^\top & 0 \end{pmatrix}\begin{pmatrix} q \\ g \end{pmatrix} = \begin{pmatrix} 0 \\ 1 \end{pmatrix}.$$
The LP curve is $F = 0$, $g = 0$ with two free parameters. Update the borders $v_{\text{bor}}, w_{\text{bor}}$ from the current null vectors after each accepted step.

**Hopf.** The eigenvectors satisfy $Aq = i\omega q$ and $A^\top p = -i\omega p$. Use the normalization $\langle q,q\rangle = 1$ and $\langle p,q\rangle = 1$, where $\langle a,b\rangle = \bar a^\top b$. The first Lyapunov coefficient (Kuznetsov) is
$$l_1 = \frac{1}{2\omega}\,\mathrm{Re}\Big(\langle p, C(q,q,\bar q)\rangle - 2\langle p, B(q, A^{-1}B(q,\bar q))\rangle + \langle p, B(\bar q, (2i\omega I - A)^{-1}B(q,q))\rangle\Big).$$
The value of $l_1$ depends on the normalization of $q$; only its sign is invariant. Always report which normalization was used. Every stored LP and H point records its normalization as a string (`|q|=1, p'q=1, p'F_alpha>0` and `<q,q>=1, <p,q>=1`). The complex solve with $2i\omega I - A$ runs in the real form $\begin{pmatrix} A - \sigma I & \omega I \\ -\omega I & A - \sigma I \end{pmatrix}$ of $A - (\sigma + i\omega) I$, so only real LU is needed.

**Refining points on an equilibrium branch.** Newton's method on these systems, with exact Jacobians from the `JacU`, `JacP` and `Dir` entries:
- LP: $F = 0$, $g = 0$ in $(u, \alpha)$, with $g$ from the bordered system above and borders from the null vectors of $A$ at the located point. The derivative of $g$ with respect to a component $z$ of $(u,\alpha)$ is $g_z = -w^\top (A_z q)$, where $w$ solves the adjoint system $\begin{pmatrix} A^\top & v_{\text{bor}} \\ w_{\text{bor}}^\top & 0 \end{pmatrix}\begin{pmatrix} w \\ h \end{pmatrix} = \begin{pmatrix} 0 \\ 1 \end{pmatrix}$.
- H: the standard extended system in $(u, \alpha, q_r, q_i, \omega)$ with $3n + 2$ equations: $F = 0$, $A q_r + \omega q_i = 0$, $A q_i - \omega q_r = 0$, $c^\top q_r = 1$, $c^\top q_i = 0$, where $c$ is the real part of the eigenvector at the located point. It needs only first and second derivatives.
- BP: $F(x) + b\varphi = 0$, $F_x^\top \varphi = 0$, $\varphi^\top \varphi = 1$ in $(x, b, \varphi)$, with $2n + 2$ equations; $b = 0$ at the solution.

**Two-parameter curves.** Phase 4 continues LP and H curves in `pc-engine` (`continue_lp_curve`, `continue_hopf_curve`) under the same `run_branch` as equilibrium branches. They are reachable from the C ABI (problem `type` `LP` or `H`) and from MATLAB (`Type="LP"|"H"`, Section 11). The unknown is $x = (u, a_1, a_2)$ for the LP curve and $x = (u, a_1, \kappa, a_2)$ for the H curve, and `CurveSetup` gives the two free parameters and a start state. On a curve, `Point.u` is $x$ without its last entry, `Point.alpha` is $a_2$, `Options::bounds` applies to $a_2$, `Point.tests` is NaN and the codim-2 test values are in `Point.codim2`. The start tangent is the unit null vector of the curve Jacobian. `Options::direction` $-1$ reverses it.

**LP curve.** The equations are $F = 0$ and $g = 0$ with $g$ from the bordered system above. The zero set of $g$ does not depend on the borders, so each evaluation of the test functions replaces them by the unit null vectors $q$ and $p$ at that point. The sign of $q$ and $p$ stays continuous because $v_{\text{bor}}^\top q = 1$ holds for the old borders.

**Minimally augmented Hopf curve.** Let $M = A^2 + \kappa I$. At a Hopf point $M$ has the eigenvalue 0 on the real eigenplane $E$ of the pair, so its nullity is 2. On $E$, $A = \mu I + \omega J$ with $J$ the rotation by 90 degrees, and $M|_E = aI + bJ$ with $a = \mu^2 - \omega^2 + \kappa$ and $b = 2\mu\omega$. With $n \times 2$ borders $V$ and $W$ solve
$$\begin{pmatrix} M & W \\ V^\top & 0 \end{pmatrix}\begin{pmatrix} X \\ G \end{pmatrix} = \begin{pmatrix} 0 \\ I_2 \end{pmatrix}.$$
Then $G e_1 = 0$ exactly when $M|_E = 0$, that is when $\mu = 0$ and $\kappa = \omega^2$. The curve is $F = 0$, $G_{11} = 0$, $G_{21} = 0$, which are $n + 2$ equations in $n + 3$ unknowns. This is Govaerts' minimally extended system for a nullity-2 matrix with the second column of $G$ left out (Govaerts 2000, Sec. 5.6). The gradient is $G_z[i,0] = -Y_i^\top M_z X_0$, with $Y$ from the adjoint system $\begin{pmatrix} M^\top & V \\ W^\top & 0 \end{pmatrix}\begin{pmatrix} Y \\ H \end{pmatrix} = \begin{pmatrix} 0 \\ I_2 \end{pmatrix}$. For $z$ in $(u, a_1, a_2)$, $M_z = A_z A + A A_z$, so $G_z[i,0] = -\big(Y_i \cdot A_z(AX_0) + (A^\top Y_i)\cdot(A_z X_0)\big)$. For $\kappa$, $M_\kappa = I$ and $G_\kappa[i,0] = -Y_i \cdot X_0$. The borders are replaced by an orthonormal basis of the columns of $X$ and $Y$ at each evaluation of the codim-2 tests. The start $\kappa_0 = \omega^2 - \mu^2$ comes from the critical pair of $A$ at the start state. A start whose residual exceeds `tol_f` is a `BadProblem` error. The Brusselator Hopf curve $b = 1 + a^2$ is an exact check ($\kappa = a^2$, equilibrium $(a, b/a)$), and the run matches it to $10^{-9}$.

**Codim-2 points.** `Point.codim2` holds the test values in the order below, and `Problem::codim2_label(i, eigs)` names a zero. `locate.rs` treats the three equilibrium tests and the codim-2 tests as one index space. The zero is located by the Illinois search of Section 5 and then polished by Newton's method along the curve: the slope of the test is a forward difference along the tangent, each step is a corrector solve of that length, and the run ends when a step is shorter than `tol_x`. A point that converges has `refined = true` and is accurate to $10^{-10}$. If the test is undefined next to the point, a step is longer than the search step, the corrector fails or the iteration does not converge in 8 steps, the Illinois point is kept with `refined = false`, accurate to $10^{-8}$. A codim-2 sign change counts as a zero only if the located value is at most $10^{-2}$ times the smaller end value of the step, so a pole is not reported. A zero that `codim2_label` rejects gives no special point and no warning. A curve run also looks for specials on its first step.
- On LP curves, with unit $q$ and $p$:
  - CP: $\langle p, B(q,q)\rangle$. It stays smooth through a BT point, where $\langle p, q\rangle$ vanishes.
  - BT: $\langle p, q\rangle$.
  - ZH: $\psi_H$ of the eigenvalues without the one of smallest modulus. A zero from two real eigenvalues of opposite sign is a neutral saddle and is not labeled (`classify_h_zero`).
- On H curves, with $\omega = \sqrt{\kappa}$:
  - GH: $l_1$ at $\omega$ for $\kappa > 0$, NaN otherwise.
  - BT: $\kappa$. It changes sign where $\omega$ passes through 0, so the curve continues through BT into the neutral saddle side.
  - ZH: the product of the real parts of the eigenvalues outside the critical pair. It is labeled only if the eigenvalue nearest the imaginary axis outside the pair is real.
  - HH: $\psi_H$ of the eigenvalues outside the critical pair. It needs at least two of them and is labeled only if the zero is a conjugate pair.
  - ZH and HH are NaN for $\kappa \le 0$, since the critical pair is not a Hopf pair there.

**Normal form coefficients.** The formulas follow Kuznetsov (1999) and his book (Section 15), with $B, C, D, E$ the second to fifth derivatives of $F$ in the state at the point.
- CP: $c = \tfrac{1}{6}\langle p, C(q,q,q) + 3B(q, h_2)\rangle$ with $Aq = 0$, $A^\top p = 0$, $\langle p,q\rangle = 1$, $Ah_2 = \langle p, B(q,q)\rangle q - B(q,q)$ and $\langle p, h_2\rangle = 0$. The value depends on the scale of $q$ and its sign does not. The normalization string is `|q| = 1 before scaling, <p,q> = 1, <p,h2> = 0`.
- BT: with the chains $Aq_0 = 0$, $Aq_1 = q_0$, $A^\top p_1 = 0$, $A^\top p_0 = p_1$ and $\langle q_0,p_0\rangle = \langle q_1,p_1\rangle = 1$, $\langle q_1,p_0\rangle = \langle q_0,p_1\rangle = 0$, the normal form $\dot w_0 = w_1$, $\dot w_1 = a w_0^2 + b w_0 w_1$ has $a = \tfrac12\langle p_1, B(q_0,q_0)\rangle$ and $b = \langle p_0, B(q_0,q_0)\rangle + \langle p_1, B(q_0,q_1)\rangle$. Here $|q_0| = 1$ and the sign of $q_0$ makes $a > 0$. This sign convention is a choice of this project, and the stored normalization string says so.
- GH: $l_2 = \mathrm{Re}\,G_{32} / (12\omega)$ from the recursion for $h_{20}, h_{11}, h_{30}, G_{21}, h_{21}, h_{31}, h_{22}$ in Kuznetsov's Bautin section, with $\langle q,q\rangle = \langle p,q\rangle = 1$ and $\langle p, h_{21}\rangle = 0$. The normalization string is `<q,q>=1, <p,q>=1, <p,h21>=0`. For the Bautin form of Test 9 with $|q| = 1$ the expected value is $l_2 = 4s$, and a near-identity coordinate change of the model gives the same value to $10^{-6}$.
- ZH: with $Aq_0 = 0$, $Aq_1 = q_0$, $A^\top p_1 = 0$, $A^\top p_0 = p_1$ for the double-zero chain, and $q_1, p_1$ the eigenvector pair for $\pm i\omega$, the coefficients follow Kuznetsov (1999, Section 8): $G_{200} = \langle p_0, B(q_0,q_0)\rangle$, $G_{110} = \langle p_1, B(q_0,q_1)\rangle$, $G_{011} = \langle p_0, B(q_1,\bar q_1)\rangle$, then $b = G_{200}/2$, $c = G_{011}$, $d = G_{110} - i\omega G_{300}/(3G_{200})$ and $e = \tfrac12\mathrm{Re}\,[G_{210} + G_{110}(\mathrm{Re}\,G_{021}/G_{011} - G_{300}/G_{200} + G_{111}/G_{011}) - G_{021}G_{200}/(2G_{011})]$, with $G_{300}, G_{111}, G_{210}, G_{021}$ from the $h_{200}, h_{020}, h_{110}, h_{011}$ solves of that section. The sign of $q_0$ makes $b > 0$, a choice of this project like $a > 0$ at BT. $G_{200} = 0$ or $G_{011} = 0$ is an error. `Extras.coefficient` is $b$, `coefficient2` is $c$, and `values` holds `re_d`, `im_d` and `e`. The normalization string is `b>0, |q0|=1, <p0,q0>=1, <q1,q1>=1, <p1,q1>=1`.
- HH: with the eigenpairs of $\pm i\omega_1$ and $\pm i\omega_2$ ordered so that $\omega_1 > \omega_2$, and $\langle q_j,q_j\rangle = \langle p_j,q_j\rangle = 1$, the cubic coefficients follow Kuznetsov (1999, Section 9). The $h_{1100}, h_{2000}, h_{0011}, h_{0020}, h_{1010}, h_{1001}$ solves give $G_{2100}, G_{1011}, G_{1110}, G_{0021}$, whose real parts are $P_{11}, P_{12}, P_{21}, P_{22}$. `coefficient` is $P_{11}$, `values` holds `re_p12`, `re_p21`, `re_p22` and `omega2`, and `omega` is $\omega_1$. $\omega_1 = \omega_2$ and $\omega_1 = 2\omega_2$ are errors. The normalization string is `<q1,q1>=1, <p1,q1>=1, <q2,q2>=1, <p2,q2>=1, w1>w2`. The fifth-order coefficients $S_1$ and $S_2$ are not computed. The open copy of the paper has misprints in those formulas and no second source confirms them, so rule 9 keeps them out. They stay open in `docs/STATUS.md`.

**Branch switching at BP.** Compute the second tangent from the null space of the extended Jacobian and the algebraic branching equation (Allgower and Georg; Govaerts). At a simple BP $x^*$, $\varphi_1, \varphi_2$ span the kernel of the $n \times (n+1)$ matrix $F_x$ and $\psi$ spans its left kernel. With $c_{ij} = \psi^\top F_{xx}[\varphi_i, \varphi_j]$, the tangents of the two branches are $\beta_1\varphi_1 + \beta_2\varphi_2$ for the roots of $c_{11}\beta_1^2 + 2c_{12}\beta_1\beta_2 + c_{22}\beta_2^2 = 0$. The new branch takes the root farther from the current tangent. A negative discriminant or a double root means the BP is not simple, and switching stops with an error.

## 7. Limit cycles

**Formulation.** Rescale time to $\tau \in [0,1]$:
$$\dot u = T f(u,\alpha), \qquad u(0) = u(1), \qquad \int_0^1 u(\tau)^\top \dot u_{\text{prev}}(\tau)\, d\tau = 0.$$
The integral is the phase condition.

**Discretization.**
- Use $N$ mesh intervals with $m$ Gauss-Legendre collocation points each. On each interval, $u$ is a degree-$m$ polynomial stored by its values at $m+1$ points, and neighboring intervals share endpoints.
- Unknowns: $n(Nm+1) + 2$ (the mesh values, $T$ and $\alpha$).
- Equations: $nNm$ collocation equations, $n$ periodicity conditions, 1 phase condition and 1 PALC equation.
- Evaluate the phase integral with the same Gauss weights.
- $N$ and $m$ stay fixed for the whole run. Mesh adaptation moves the $N+1$ mesh points and keeps both, so the row stride of Section 10 does not change during a run.
- The PALC equation scales the profile unknowns by $1/\sqrt{Nm}$, so the arclength approximates the $L^2$ norm of the orbit. $T$ and $\alpha$ are not scaled.

**Linear solves by condensation of parameters** (Doedel, Keller and Kernévez 1991; AUTO-07p):
1. On each interval, eliminate the interior unknowns with dense LU (faer).
2. This leaves a block system in the mesh-point values plus the bordering rows and columns.
3. Solve that reduced system with faer's sparse LU. `pc-linalg` chooses between faer's simplicial and supernodal variants itself, starting with the simplicial one, instead of using faer's automatic choice. Tests compare the result with a sparse LU of the full matrix.

Assemble and condense in Rust. Run sequentially by default, and condense the intervals in parallel on the current rayon pool when the interval elimination work, $N \cdot nm \cdot n_i (n_i + 2n + k + 1)$ multiply-adds with $n_i = n(m-1)$ interior columns and $k$ bordering columns, is at least `PARALLEL_WORK` $= 2 \cdot 10^7$ (`CondenseShape::parallel_pays`). Phase 5 measured this threshold on the default pool, with one thread per logical CPU (`docs/STATUS.md`, P5 package 7). The parallel and sequential solves give the same bits. Large buffers are allocated with `try_reserve` or `MemBuffer::try_new` and fail with `OutOfMemory`, since a failed allocation in `Vec` or in dyn-stack's `MemBuffer::new` aborts the MATLAB process.

**Floquet multipliers.**
- The condensed blocks give the linear map from $u(0)$ to $u(1)$.
- v1: form the monodromy matrix as a product of the blocks, compute its eigenvalues, and check that one multiplier satisfies $|\mu_1 - 1| \le 10^{-6}$. Flag the result when the check fails.
- Later: replace the product with a periodic Schur method (Fairgrieve and Jepson 1991), so that multipliers spanning many orders of magnitude stay accurate.

**Test functions on cycle branches.** The products run over the nontrivial multipliers.
- **LPC:** $\psi_{LPC}$ is the $\alpha$ component of the tangent, which changes sign at a fold of the cycle branch. The product $\prod_i (\mu_i - 1)$ over the nontrivial multipliers also vanishes there, but P5 does not use it.
- **PD:** $\psi_{PD} = \prod_i (\mu_i + 1)$.
- **NS:** $\psi_{NS} = \prod_{i<j} (\mu_i \mu_j - 1)$. This also vanishes for a real pair with product 1, which is a neutral saddle cycle; check the multipliers.

**Mesh adaptation.** Redistribute the mesh so that a monitor of the $m$-th derivative jumps is equidistributed (Russell and Christiansen 1978; AUTO-07p). `crates/pc-engine/src/cycle/mesh.rs` ports AUTO-07p's EQDF, NEWMSH and INTERP (see `THIRD_PARTY_NOTICES.md`). It runs every `Options::mesh_adapt` accepted points (default 3, 0 turns it off) and at most once per point after a failed corrector. When every $m$-th derivative is below $10^{-7}$ the mesh stays, and a new mesh that is not strictly increasing or not finite is refused. Every point records its mesh.

**Starting a cycle branch from a Hopf point.** Use the initial guess
$$u(\tau) = u_0 + \varepsilon\, \mathrm{Re}\big(q\, e^{2\pi i \tau}\big), \qquad T = \frac{2\pi}{\omega},$$
with $\varepsilon$ = `Options::h0`. If the corrector fails, retry with $\varepsilon/2$, up to 4 times. The run always moves away from the equilibrium, so `Options::direction` $< 0$ is ignored with a warning.

**Period doubling switch.** Start the doubled branch at period $2T$ with an initial guess perturbed along the eigenfunction $\psi$ of multiplier $-1$. $\psi$ is solved from the condensed system of the PD orbit. The orbit and $\psi$ (with $-\psi$ on the second half) are doubled onto $[0, 1]$ and interpolated onto the new $N$ and $m$, which may differ from those of the PD orbit. The new mesh takes its $N + 1$ points evenly in the index of the doubled mesh. The first orbit is corrected at $\varepsilon$ = `Options::h0` along that direction, with the same halving as a Hopf start. The start warns when the multiplier closest to $-1$ is more than $10^{-6}$ away from it and refuses a complex one. Both directions give the same orbits half a period apart, so `Options::direction` $< 0$ is ignored with a warning.

**Trivial multiplier.** A point with no multiplier within $10^{-6}$ of 1 gets a warning on its branch.

## 8. Codim-1 cycle curves (phase E6)

Continue LPC, PD and NS curves in two parameters $(a_1, a_2)$ with minimally augmented defining systems on the collocation discretization of Section 7 (Doedel, Govaerts and Kuznetsov 2003, "Computation of periodic solution bifurcations in ODEs using bordered systems", DGK below). The periodic normal forms of phase E7 follow Kuznetsov, Govaerts, Doedel and Dhooge (2005) for codim 1 and De Witte, Della Rossa, Govaerts and Kuznetsov (2013) for codim 2.

**Unknowns.** An LPC or PD curve has $x = (u, T, a_1, a_2)$, where $u$ is the orbit at the $Nm+1$ base points. An NS curve adds $\kappa = \cos\theta$ of the critical multipliers $e^{\pm i\theta}$, so $x = (u, T, a_1, \kappa, a_2)$. The row alpha is $a_2$, and `Point.u` holds everything before it.

**Outer system.** The rows of Section 7 (collocation, periodicity and the phase condition) come first, then the defining equation $G = 0$ (one row for LPC and PD, two for NS), then PALC. $T$, $a_1$, $\kappa$ and $a_2$ border the condensed system, which has $k = 3$ bordering columns for LPC and PD and $k = 4$ for NS. The phase reference, the PALC scaling and mesh adaptation (`options.mesh_adapt`) work as on a cycle branch.

**Defining functions.** Each $G$ is the bottom right entry (or $2 \times 2$ block) of the solution of a bordered inner system $N$ that is singular on the curve. With $N (v, G)^\top = (0, 1)^\top$ and $(w, G)\, N = (0, 1)$, the derivatives are $G_z = -w^\top N_z v$ (DGK §3), from one factored solve and one transposed solve of the condensed inner system. The second derivatives $f_{xx}$ and $f_{xp}$ in $N_z$ are exact directional derivatives from the JIT (`Model2::a_z_q`).
- **LPC.** $N$ is the Jacobian of the periodic orbit system in $(u, T)$, with the phase row of Section 7 and its fixed reference in place of DGK's $\mathrm{Int}_f$ row, bordered by one row and one column. $G = 0$ is then exactly the singularity of the discrete Jacobian in $(u, T)$. The zero set does not depend on the phase vector as long as $\int_0^1 \varphi^\top \dot u \, d\tau \ne 0$. The inner condensation has $k = 2$.
- **PD.** $N = [D - T f_x;\ v(0) + v(1)]$, bordered by one row and one column (DGK, PD system), with no $T$ unknown. The inner condensation has $k = 1$.
- **NS.** DGK write the NS system on $[0, 2]$ with $v(0) - 2\kappa v(1) + v(2) = 0$. The engine writes it exactly on $[0, 1]$ with a doubled state $(v_a, v_b)$ of size $2n$ and the boundary conditions $v_b(0) - v_a(1) = 0$ and $v_a(0) - 2\kappa v_a(1) + v_b(1) = 0$, bordered by two rows and two columns. The curve continues $G_{11}$ and $G_{21}$, the first column of $G$, from one factored solve and two transposed solves. $G_\kappa$ comes from the $2 v_a(1)$ term. The inner condensation has $n \to 2n$ and $k = 2$.

For $|\kappa| < 1$ the real kernel of $M^2 - 2\kappa M + I$ has even dimension, so a zero first column of $G$ forces $G = 0$, and the two equations have no spurious zeros. For $|\kappa| > 1$ (a neutral saddle cycle) they can: the branch warns when a point lacks one of the real multipliers $\mu, 1/\mu$ with $\mu + 1/\mu = 2\kappa$, within $10^{-6}$ relative.

**Borders.** The row border over the profile is the previous right kernel vector. After mesh adaptation it is interpolated onto the new mesh. The column border lies on the boundary rows (and the phase row for LPC), so it does not depend on the mesh. Both are refreshed at every accepted point. At the start they come from two steps of inverse iteration from a generic border, and the NS start uses two Weyl sequences for its two borders.

**Start.** A curve starts from an LPC, PD or NS special point of an LC branch, with its orbit, period and mesh.
- When the requested `ntst` and `ncol` differ from those of the point, the orbit is regridded onto $N + 1$ mesh points taken evenly in the index of the old mesh (Section 7, period doubling switch).
- An NS start takes $\kappa$ from the complex multiplier closest to the unit circle, and a start with no complex pair is `BadProblem`.
- Section 7 locates these points with other test functions, so $G$ is small at the start but not zero. Newton first corrects the start at fixed $a_2$, and a failure is `BadProblem` with the hint "start from a matching special point of a cycle branch".
- The first tangent comes from a bordered solve with the row $e_{a_2}$, or the next unknown when that solve fails. It points toward growing $a_2$ times the sign of `Options::direction`.

**Codim-2 tests.** They use the Floquet multipliers of the point. Each curve leaves out the trivial multiplier and its own critical multipliers, removing each time the multiplier nearest to the excluded value, so a zero comes from one more multiplier, or pair, on the unit circle. A test over an empty set of remaining multipliers is NaN.

| Curve | Labels and tests |
|---|---|
| LPC | LPPD $= \prod(\mu + 1)$, LPNS $= \prod_{i<j}(\mu_i \mu_j - 1)$, without the double multiplier 1 |
| PD | LPPD $= \prod(\mu - 1)$, PDNS $= \prod_{i<j}(\mu_i \mu_j - 1)$, without 1 and $-1$ |
| NS | R1 $= \kappa - 1$, R2 $= \kappa + 1$, R3 $= \kappa + \tfrac12$, R4 $= \kappa$, LPNS $= \prod(\mu - 1)$, PDNS $= \prod(\mu + 1)$, without 1 and the roots of $\mu^2 - 2\kappa\mu + 1$ |

A zero of LPNS on an LPC curve or of PDNS on a PD curve gets its label only when the pair whose product is closest to 1 is complex, since a real pair with product 1 is a neutral saddle. On an LPC curve the multiplier 1 is double with a Jordan block, so the trivial multiplier check of Section 7 uses the mean of the two multipliers nearest to 1.

**E7.** CPC, GPD and CH need periodic normal forms, and R1 on an LPC curve and R2 on a PD curve need a test that the exclusion rule cannot give. Section 8a defines them, and the curve runs of this section label them (E7b).

## 8a. Periodic normal forms of cycle bifurcations (phase E7)

Phase E7 computes one normal form coefficient at each LPC, PD and NS point, and uses its zero as a codim-2 test on the curves of Section 8. It uses periodic normalization (Kuznetsov, Govaerts, Doedel and Dhooge 2005, KGDD below), which needs no derivatives of the Poincaré map. The 2005 paper is not available as a free text. The formulas below were checked against two free restatements: De Witte, Della Rossa, Govaerts and Kuznetsov (arXiv 1111.4445, DWDGK) and Bosschaert, Lentjes, Spek and Kuznetsov (arXiv 2505.19786, BLSK, the delay version, taken at the ODE limit). Equation numbers below are those of the restatements.

E7 has two parts. E7a computes the coefficients at special points and at the points of a curve, and changes no interface. E7b adds the codim-2 labels (CPC, GPD, CH, R1 on LPC, R2 on PD) to the curve runs. It changes the per-point row layout and the `codim2_labels` lists of Section 10. The owner approved that change on 2026-11-06, and both parts are done.

**Notation.** The cycle is $u_0(t)$ with period $T$, $F = f(u_0) = \dot u_0$, $A(t) = f_x(u_0(t))$, and $B$, $C$ are the second and third derivatives of $f$ in $u$ at $u_0(t)$, as symmetric multilinear forms. The inner product is $\langle u, v\rangle = \bar u^\top v$. Every integral runs over $[0, T]$ and every function is $T$-periodic unless the text says it is antiperiodic. A prime is $d/dt$.

**Time scale.** The engine solves on $\tau = t/T \in [0, 1]$ with $U(\tau) = u_0(T\tau)$. Each equation below is written once in $t$ and solved in $\tau$ with $d/dt = T^{-1} d/d\tau$, $\int_0^T g\, dt = T \int_0^1 g\, d\tau$, $A = f_x(U)$ and $F = f(U) = U_\tau / T$. The normalizations $\int_0^T \langle v, v\rangle\, dt = 1$ become $T \int_0^1 \langle V, V\rangle\, d\tau = 1$. A test model with $T = 1$ would hide a missing factor of $T$, so every oracle below has $T = \pi$.

**LPC.** The normal form is $\tau' = 1 + \xi + a\xi^2$, $\xi' = b\xi^2$ (BLSK; DWDGK Appendix A.2.1 has the same form after $\xi \to -\xi$). Solve
$$\varphi_1' - A\varphi_1 = -F,\quad \int \langle \varphi_1, F\rangle = 0,$$
$$\varphi^{*\prime} + A^\top \varphi^* = 0,\quad \int \langle \varphi^*, \varphi_1\rangle = 1,$$
$$b = \tfrac12 \int \langle \varphi^*,\ B(\varphi_1, \varphi_1) - 2A\varphi_1\rangle \qquad \text{(BLSK eq. 60)}.$$
DWDGK writes $v' - Av - F = 0$ (eq. 15, 21, §3.1) and $b = \tfrac12 \int \langle \varphi^*, B(v, v) + 2Av\rangle$. Since $v = -\varphi_1$ and the DWDGK adjoint is $-\varphi^*$, the two conventions give opposite signs. The engine uses the BLSK one. The sign does not change the nondegeneracy test $b \ne 0$ or the detection of CPC. $b$ does not change under a phase shift $\varphi_1 \to \varphi_1 + cF$ or under a constant invertible linear change of coordinates.

**PD.** The normal form is $\tau' = 1 + a\xi^2$, $\xi' = c\xi^3$, supercritical for $c < 0$. Solve (DWDGK eq. 28–35)
$$v' = Av,\quad v(T) = -v(0),\quad \int \langle v, v\rangle = 1 \quad (28)$$
$$\varphi^{*\prime} + A^\top \varphi^* = 0 \text{ (periodic)},\quad \int \langle \varphi^*, F\rangle = 1 \quad (29)$$
$$v^{*\prime} + A^\top v^* = 0,\quad v^*(T) = -v^*(0),\quad \int \langle v^*, v\rangle = 1 \quad (30)$$
$$\alpha_1 = \tfrac12 \int \langle \varphi^*, B(v, v)\rangle \quad (32)$$
$$h_2' - Ah_2 - B(v, v) + 2\alpha_1 F = 0,\quad \int \langle \varphi^*, h_2\rangle = 0 \quad (33)$$
$$c = \tfrac16 \int \langle v^*,\ C(v, v, v) + 3B(v, h_2) - 6\alpha_1 A v\rangle \quad (35).$$
$h_2$ is $T$-periodic and the integrand of $c$ is $T$-periodic. BLSK eq. 64 prints $\tfrac13$ for the prefactor, which equals this formula if its integral runs over $[0, 2T]$. The engine integrates over $[0, T]$ with $\tfrac16$, and the exact oracle of test 2 below confirms it.

**NS.** The normal form is $\xi' = i\omega\xi + d\,\xi|\xi|^2$, with $\omega = \theta / T$ for the critical multipliers $e^{\pm i\theta}$, $0 < \theta < \pi$, and supercritical for $\operatorname{Re} d < 0$. Solve (DWDGK eq. 42–45)
$$v' - Av + i\omega v = 0,\quad \int \langle v, v\rangle = 1,\qquad v^{*\prime} + A^\top v^* + i\omega v^* = 0,\quad \int \langle v^*, v\rangle = 1 \quad (42)$$
$$h_{20}' - Ah_{20} + 2i\omega h_{20} - B(v, v) = 0 \quad (43)$$
$$\alpha_1 = \int \langle \varphi^*, B(v, \bar v)\rangle \quad (44)$$
$$h_{11}' - Ah_{11} - B(v, \bar v) + \alpha_1 F = 0,\quad \int \langle \varphi^*, h_{11}\rangle = 0 \quad (45)$$
$$d = \tfrac12 \int \langle v^*,\ B(h_{20}, \bar v) + 2B(h_{11}, v) + C(v, v, \bar v) - 2\alpha_1 A v\rangle + i\alpha_1\omega \quad \text{(BLSK supplement S9)}.$$
All functions are $T$-periodic and $\varphi^*$ is as for PD. Only $\operatorname{Re} d$ gives the criticality and the CH test. $\operatorname{Im} d$ changes sign with the branch chosen for $\omega$, which is why the engine fixes $0 < \theta < \pi$. The tests assert $\operatorname{Im} d$ in every NS variant of test 3, and the variant with $\alpha_1 = 0.2546$ gives the same $\operatorname{Im} d$ as the plain model to $10^{-5}$. With $\langle v, v\rangle = 1$ for a complex $v$ the real plane coordinate is $2\operatorname{Re}(\xi v)$, so $|w|^2 = 2|\xi|^2 / T$ and the complex coefficient doubles, as for $l_1$ in Section 9.

**Inputs.** $B$ and $C$ come from the `Dir` forms of the JIT that `normal.rs` already uses for equilibria, and $A$ from `Model2`. The `pc_ir::check` test already compares those forms with finite differences to order 5, so E7 needs no change in `pc-ir` or `pc-jit`. Each linear periodic problem above is discretized on the mesh of the cycle ($N$ intervals, $m$ Gauss points), solved with the condensation of Section 7, and integrated with the Gauss weights.

**Outputs (E7a).** At an LPC, PD or NS special point of a cycle branch, `Extras.coefficient` is $b$, $c$ or $\operatorname{Re} d$, `coefficient2` is $\operatorname{Im} d$ for NS and null otherwise, and `normalization` names the conditions used (for PD, `<v,v>=1, <phi*,F>=1, <v*,v>=1`). The sign gives the criticality, as $l_1$ does for H, and the engine adds no label text. A function in `cycle/normal.rs` also evaluates the coefficient at any point of an LPC, PD or NS curve, so a curve run can be checked against the closed forms below. E7a adds no field to `Point`, the run JSON or the C ABI.

**Codim-2 tests (E7b).** The coefficient is evaluated at every accepted point of an LPC, PD or NS curve and appended to the tests of Section 8, after the existing ones, so existing indexes keep their meaning.

| Curve | `codim2_labels` |
|---|---|
| LPC | `["LPPD","LPNS","CPC","R1"]`, with CPC $= b$ and R1 $= \prod(\mu - 1)$ |
| PD | `["LPPD","PDNS","GPD","R2"]`, with GPD $= c$ and R2 $= \prod(\mu + 1)$ |
| NS | `["R1","R2","R3","R4","LPNS","PDNS","CH"]`, with CH $= \operatorname{Re} d$ |

R1 and R2 are multiplier tests over the multipliers left after the exclusion rule of Section 8, and are NaN for $n = 2$. The sources give only the Jordan-structure definitions of R1 and R2 and the codim-2 coefficients (DWDGK §3.4–3.5, eq. 64, 67, 84), not a test function. The label means that a further multiplier is at $+1$ (R1) or $-1$ (R2), and the engine does not check for the Jordan block. The error of the multipliers near a Jordan block limits the location of these two labels to about $10^{-5}$. The new tests add two columns to a row of an LPC or PD curve (26 values at $n = 2$, `ntst = 2`, `ncol = 2`, where there were 24) and one to a row of an NS curve (30, where there were 29), and they change the `codim2_labels` lists of Section 10 and the label lists in `rows2branch.m` and `Branch.m`. `cycle_stride` in `pc-ffi` follows the label list, so no C function signature changes and `abi_version` stays 1.

The engine evaluates the coefficient inside `codim2_tests`, and a point where the normal form fails gets NaN for that test. The coefficients come from bordered solves that can go singular at a resonance, and a sign change through such a pole would otherwise be located as a zero. `locate_one` in `locate.rs` already drops a codim-2 zero whose value at the located point is above `POLE_TOL` ($10^{-2}$) times the smaller end value of the step, and that guard covers all five new tests. Every expected zero below was located, so the guard dropped none of them, and no pole was seen in these models.

**First-point rule.** The first point of a run is the start the caller chose. A test that is exactly zero there gets its label on point 0, for the equilibrium tests and the codim-2 tests alike, because no earlier step reached that point and nothing else would report it. The label is added only when the test is not zero or undefined at the second point, since a test that stays zero is no crossing: the coefficient of a model that has none is zero along the whole curve. A codim-2 value that is zero at the start only up to rounding is treated the same way when the sign change to the second point defeats the search. The search fails there because the pole guard compares the located value with the smaller end value, and at a rounding-level start that is smaller than any value the search can reach. In that case the value $a$ at the start and $b$ at the second point satisfy $|a| \le \texttt{POLE\_TOL}\,|b|$, so the run labels point 0 and adds no warning. The bound is the guard's own tolerance, applied to the start instead of to the located value. The rule applies only to a failed search, so a zero near the start that the search does place is still a label at its own point, and a pole at the start ($|a|$ large) still gives the warning. Rounding decides the sign of such a start value, so a run in one direction has the sign change and the label, and a run in the other direction has neither. A run that switches onto a branch at a branch point sets `start_is_special`, skips detection on its first step and carries no label at the start, since the parent branch holds it.

**Out of scope.** Codim-2 normal form coefficients, a center manifold of dimension above 3, homoclinic orbits (E8, Section 8b) and delay equations beyond Sections 8c to 8e.

## 8b. Homoclinic orbits to a saddle (phase E8, part a)

Phase E8a continues an orbit homoclinic to a hyperbolic saddle in two free parameters $(a_1, a_2)$ and locates the codim-2 points on that curve that need only the eigenvalues of the saddle and the ends of the orbit. The formulation follows Beyn (1990) and Champneys, Kuznetsov and Sandstede (1996, CKS below), and the test functions and their order follow HomCont, the homoclinic part of AUTO-07p (`src/homcont.f90`, BSD-3, which rule 3 allows us to port). The adjoint problem (inclination flips and the orientation index, HomCont tests 13 and 14), saddle-node homoclinic orbits (tests 15 and 16), heteroclinic orbits and Lin's method are phase E8b and are not part of this section.

**Unknowns and equations.** The engine solves on $\tau \in [0, 1]$ with the collocation mesh of Section 7 ($N$ intervals, $m$ Gauss points). The unknowns are the orbit $u$ on the mesh ($n(Nm+1)$ values), the equilibrium $x_0$ ($n$ values) and $(a_1, a_2)$. The truncation time $T$ is fixed at its start value for the whole run, as in HomCont. The equations are
$\dot u = T f(u, p) \text{ by collocation, with no periodic condition},$$
$$f(x_0, p) = 0 \quad (n \text{ rows}),$$
$$L_s^\top (u(0) - x_0) = 0 \quad (n_s \text{ rows}),\qquad L_u^\top (u(1) - x_0) = 0 \quad (n_u \text{ rows}),$$
$$\int_0^1 \dot u_{\text{prev}}(\tau)^\top \big(u(\tau) - u_{\text{prev}}(\tau)\big)\, d\tau = 0,$$
where $A = f_x(x_0, p)$ has $n_s$ eigenvalues with negative real part and $n_u = n - n_s$ with positive real part, the columns of $L_s$ span the stable invariant subspace of $A^\top$ and the columns of $L_u$ its unstable one. $L_s^\top v = 0$ says that $v$ lies in the unstable subspace of $A$, and $L_u^\top v = 0$ that it lies in the stable one (Beyn 1990). $u_{\text{prev}}$ is the previous accepted point, or the start orbit at the first point. The phase condition subtracts $u_{\text{prev}}$, unlike the one of Section 7, because $\int_0^1 u^\top \dot u\, d\tau$ is not zero on an orbit that is not periodic. The count is $n(Nm+1) + n + 2$ unknowns and $n(Nm+1) + n + 1$ equations, so the solution set is a curve, and PALC adds the last row.

**Invariant subspaces.** The engine computes the subspaces from the matrix sign function, not from eigenvectors, because eigenvectors break down at a Jordan block and the Belyakov test below passes through one. It runs the Newton iteration $S_{k+1} = \tfrac12(S_k + S_k^{-1})$ from $S_0 = A^\top$ with LU solves (Higham 2008, ch. 5, Newton's method), stops when $\|S_{k+1} - S_k\|_1 \le 10^{-14}\|S_{k+1}\|_1$ or after 100 steps, and takes $P_s = \tfrac12(I - S)$ and $P_u = \tfrac12(I + S)$. An orthonormal basis of the range of $P_s$ comes from QR with column pivoting, with the rank fixed at $n_s$ (and $n_u$ for $P_u$). No scaling is used. The iteration fails to converge, and the run stops with an error, if $A$ has an eigenvalue on the imaginary axis. To keep the bases smooth along the curve, the engine then rotates each new basis $V$ against the basis $C$ of the previous accepted point: it solves $(C^\top V) D = C^\top C$ and uses $L = VD$, so that $C^\top L = C^\top C$. $L$ then depends only on the subspace, not on the basis that QR returns. HomCont's PRJCTN does the same rotation and attributes it to Beyn (1990, eq. 4.4), but rotates against the basis of its previous call. The engine keeps $C$ fixed during the Newton iterations of a step, so the boundary rows are a smooth function of $(x_0, p)$, and replaces $C$ with $L$ when the point is accepted. At the first point $L$ is the QR basis itself.

**Jacobian.** The collocation rows and the phase row are those of the LC problem without the periodic wrap. The $u(0)$ and $u(1)$ columns of the boundary rows are $L_s^\top$ and $L_u^\top$. The $x_0$ and $p$ columns are forward differences of the boundary rows with step $10^{-7}(1 + |\cdot|)$ in each entry. The equilibrium rows use $f_x$ and $f_p$ from the JIT.

**Counts.** $n_s$ and $n_u$ come from the eigenvalues of $A$ at the start. Both must be at least 1, and $A$ must have no eigenvalue with real part within $10^{-8}$ of zero, or the start fails with an error. If either count changes along the curve, the run stops with an error that names the new counts. The saddle has then passed a local bifurcation, which the ZES and ZEU tests below report first.

**Mesh.** Mesh adaptation uses the equidistribution of Section 7 in its non-periodic form, as AUTO's EQDF and NEWMSH do when IPER is false: the ends of the interval are not joined when the derivative estimate is formed.

**Eigenvalues.** The eigenvalues of $A$ are sorted by real part, ascending, and a complex pair keeps the one with positive imaginary part first. $\lambda_1, \dots, \lambda_n$ is that order, $S = n_s$ is the index of the leading stable eigenvalue and $S+1$ the index of the leading unstable one. An eigenvalue counts as real when $|\operatorname{Im}\lambda| \le 10^{-13}$, the value of HomCont's COMPZERO. They are stored in the eigenvalue slot of the row, so on a HOM row `Eigenvalues` holds the eigenvalues of $A(x_0)$, not Floquet multipliers.

**Codim-2 tests.** The engine evaluates 12 tests at every accepted point. They are HomCont's tests 1 to 12 (PSIHO in `homcont.f90`), with one change: HomCont's test 1 adds the imaginary parts to test 4, and the engine instead splits the two by the type of the leading eigenvalues, so that a real neutral saddle gets one label and not two. A test is NaN where the "Defined when" column does not hold, and the locator of Section 8 does not place a zero across a NaN.

| Label | HomCont | Test | Defined when |
|---|---|---|---|
| NSA | 1 | $\lambda_S + \lambda_{S+1}$, neutral saddle | $\lambda_S$ and $\lambda_{S+1}$ real |
| BLS | 2 | $(\lambda_S - \lambda_{S-1})^2$ if $\lambda_S$ is real, else $-(\operatorname{Im}\lambda_S - \operatorname{Im}\lambda_{S-1})^2$; stable saddle to saddle-focus (Belyakov) | $n_s \ge 2$ |
| BLU | 3 | the same on $\lambda_{S+1}, \lambda_{S+2}$; unstable saddle to saddle-focus | $n_u \ge 2$ |
| NSF | 4 | $\operatorname{Re}\lambda_S + \operatorname{Re}\lambda_{S+1}$, neutral saddle-focus or bi-focus | $\lambda_S$ or $\lambda_{S+1}$ not real |
| NDS | 5 | $\operatorname{Re}(\lambda_{S-1} + \lambda_S + \lambda_{S+1})$, neutrally divergent, stable side | $n_s \ge 2$ |
| NDU | 6 | $\operatorname{Re}(\lambda_S + \lambda_{S+1} + \lambda_{S+2})$, neutrally divergent, unstable side | $n_u \ge 2$ |
| TLS | 7 | $\pm(\operatorname{Re}\lambda_S - \operatorname{Re}\lambda_{S-2})$, three leading stable | $n_s \ge 3$ |
| TLU | 8 | $\pm(\operatorname{Re}\lambda_{S+1} - \operatorname{Re}\lambda_{S+3})$, three leading unstable | $n_u \ge 3$ |
| ZES | 9 | $\operatorname{Re}\lambda_S$, zero or Hopf at $x_0$ on the stable side | always |
| ZEU | 10 | $\operatorname{Re}\lambda_{S+1}$, zero or Hopf at $x_0$ on the unstable side | always |
| OFS | 11 | $\langle f(u(1), p), w_S\rangle\, e^{-T\lambda_S/2}$, stable orbit flip | $\lambda_S$ real |
| OFU | 12 | $\langle f(u(0), p), w_{S+1}\rangle\, e^{T\lambda_{S+1}/2}$, unstable orbit flip | $\lambda_{S+1}$ real |

In TLS the sign is $+$ when $\|\operatorname{Re} v_S\|_1 > \|\operatorname{Re} v_{S-2}\|_1$ and $-$ otherwise, and TLU uses $v_{S+1}$ and $v_{S+3}$ the same way, where $v_j$ is the right eigenvector of $\lambda_j$ scaled as LAPACK's DGEEV scales it (unit 2-norm, with its largest component real). $w_j$ is the left eigenvector of a real $\lambda_j$ ($A^\top w_j = \lambda_j w_j$) with unit 2-norm. Its sign is part of OFS and OFU, so the engine fixes it: at the first point the component of largest magnitude is positive, and at every later point $w_j$ is flipped if its dot product with $w_j$ of the previous accepted point is negative. HomCont's EIGHO uses the same two rules. After a zero of ZES or ZEU the problem is no longer posed, as HomCont's notes say, and the count check above stops the run. The label names are our own.

**Starts.** The problem JSON has a required key `"start"` with no default.

1. `"orbit"`. The state buffer holds an orbit at the base points of a uniform mesh on $[0, 1]$, point-major, followed by $T$, as for the LC `orbit` start, and `mesh` is refused. The orbit is $u(\tau) = x(t_0 + T\tau)$ for a solution $x$ that leaves the saddle near $t_0$ and returns near $t_0 + T$. The engine takes the mesh point with the smallest $|f|$, finds $x_0$ from it by the Newton solve of the EP problem, and counts $n_s$ and $n_u$.
2. `"cycle"`. The state buffer holds a point of an LC branch in the LC layout (orbit at the base points, then the period), and `mesh` is required, as for the LC `pd` start, so the old $N$ comes from `mesh` and the old $m$ from the buffer length. The engine takes the mesh point with the smallest $|f|$, finds $x_0$ from it as above, shifts the periodic profile in $\tau$ so that this point sits at $\tau = 0$ and $\tau = 1$, and interpolates it onto the new mesh with the interpolation of Section 7. $T$ is the period of the cycle.

A homotopy start (HomCont's ISTART = 3) is not provided.

**Row and labels.** A HOM curve run uses `[a2, u(1..n(Nm+1)), T, x0(1..n), a1, mesh(1..N+1), eig_re(1..n), eig_im(1..n), codim2(1..12), h, newton_iters]`, stride $n(Nm+1) + N + 3n + 18$ (44 at $n = 3$, `ntst = 2`, `ncol = 2`). Its `codim2_labels` list is `["NSA","BLS","BLU","NSF","NDS","NDU","TLS","TLU","ZES","ZEU","OFS","OFU"]`. `cycle_stride` in `pc-ffi` takes $n$ for this kind, since the tail holds $x_0$. No C function signature changes and `abi_version` stays 1.

**Out of scope (E8b).** The adjoint variational problem with inclination flips and the orientation index, non-central saddle-node homoclinic orbits, heteroclinic orbits, Lin's method, a free $T$ and a homotopy start.

**Acceptance.** Every model is our own `.ode` file in `crates/pc-engine/tests/models`, written from the formulas below, and the tests are in `crates/pc-engine/tests/hom_curves.rs`. The tolerances below are upper bounds, and the first run records the measured values here, as in Section 8a.

1. **Sandstede's model, curve.** The model of Sandstede (1997) is
$$\dot x = ax + by - ax^2 + (\tilde\mu - \alpha z)x(2 - 3x),\quad \dot y = bx + ay - \tfrac32 bx^2 - \tfrac32 axy - 2y(\tilde\mu - \alpha z),$$
$$\dot z = cz + \mu x + \gamma xz + \alpha\beta(x^2(1 - x) - y^2).$$
At $\tilde\mu = \mu = 0$ and $\alpha = 0$ the plane $z = 0$ is invariant and holds the homoclinic orbit $x = 1 - w^2$, $y = -w(1 - w^2)$ with $\dot w = (1 - w^2)(b - aw)/2$, for every $a$ and $b$ with $|a| < b$. At $a = 0$, $b = 1$ it is $x = \operatorname{sech}^2(t/2)$, $y = -\operatorname{sech}^2(t/2)\tanh(t/2)$. Test 1 takes $b = 1$, $c = -2$, $\alpha = \gamma = \mu = 0$ and continues in $(a, \tilde\mu)$ from $a = -0.25$ to $a = 0.25$, at $T = 20$, 30 and 40. 2. **Orbit flip.** The same model with $(a, b, c) = (-0.5, 2.5, -1)$ and $\alpha = \gamma = 0$ has eigenvalues $2$, $-3$ and $-1$ at the origin, so the leading stable direction is the $z$ axis at $\mu = 0$. ## 8b-2. Adjoint problem and inclination flips (phase E8b, internal slice)

The first slice of E8b adds the adjoint variational problem along a HOM orbit and the two inclination-flip test functions that use it. It adds internal functions and unit tests only. It adds no label, no row field, no stride change, no JSON key, no C function and no MATLAB signature, so a HOM run writes the rows of Section 8b. Wiring the tests into a run waits for the owner decisions listed under Open questions in `docs/STATUS.md` (label count, a guard for the noise-floor zeros described below, and the choice between design A and design B).

**Sources.** AUTO-07p `src/homcont.f90` at commit 44cc1c42a888179bdbd608a40613caee9cbc4675 (BSD-3, ported, with an entry in `THIRD_PARTY_NOTICES.md`); the lecture slides cited in the research notes as "Champneys, MRI Master Class, Utrecht" (page numbers are those of the PDF); the CWI report AM-R9516 (HomCont manual), page 8; and AUTO's `auto.tex` for PAR(10) and PAR(11). Champneys, Kuznetsov and Sandstede (1996) has not been read. A formula below is marked confirmed when the code and at least one of the other three sources give it. Everything else is marked single source or deferred, and the code does not use it.

**Time convention (confirmed).** AUTO's PAR(11) is the length of the truncated interval, with $t \in [-\text{PAR}(11)/2, \text{PAR}(11)/2]$ (manual p. 8; slide 4, $2T = \text{par}(11)$). The $T$ of Section 8b is PAR(11), so every flip exponent below has $T/2$.

**Adjoint problem (confirmed).** The unknowns are $\varphi(\tau) \in \mathbb{R}^n$ on the mesh and a scalar $\gamma$ (AUTO's PAR(10), with ITWIST = 1). The equation is
$$\varphi' = T\big(-f_x(u, p)^\top \varphi + \gamma f(u, p)\big)$$
(`homcont.f90` FNHO 175-178, FFHO 252-256, INHO 886-889; slides 33 and 34; `auto.tex` 5879-5887). The boundary rows use bases of $A = f_x(x_0, p)$ itself, where the rows of the orbit problem use bases of $A^\top$: $B_u(A)^\top \varphi(0) = 0$ ($n_u$ rows) and $B_s(A)^\top \varphi(1) = 0$ ($n_s$ rows), with the columns of $B_u(A)$ and $B_s(A)$ spanning the unstable and stable invariant subspaces of $A$ (FBHO 503-523, the two PRJCTN calls with ITRANS = 2; slide 34, $P_u \varphi(-T) = 0$ and $P_s \varphi(T) = 0$). So $\varphi(0)$ lies in the stable subspace of $A^\top$ and $\varphi(1)$ in its unstable subspace. The scale of $\varphi$ is free, so AUTO adds the integral condition $\int \tilde\varphi^\top(\varphi - \tilde\varphi)\, dt = 0$ against the previous point (slide 34; ICHO writes it as a sum over the adjoint entries, and the quadrature weights were not read). In theory $\gamma = 0$, because $\frac{d}{dt}\langle \varphi, f\rangle = \gamma \|f\|^2$ and both ends of the bounded solution are orthogonal to $f$. On the truncated interval $\gamma$ is not zero, but it is of the order of the squared distance of the ends from $x_0$.

**Inclination-flip tests (confirmed).** In the notation of Section 8b,
$$\mathrm{IFS} = \langle v_S, \varphi(0)\rangle\, e^{-T\lambda_S/2},\qquad \mathrm{IFU} = \langle v_{S+1}, \varphi(1)\rangle\, e^{+T\lambda_{S+1}/2},$$
where $v_j$ is the right eigenvector of $A$ for $\lambda_j$ (HomCont tests 13 and 14, PSIHO 1941-1955, with V from EIGHO and ITRANS = 2; slide 35). Each is linear in $\varphi$. IFS is defined when $\lambda_S$ is real and IFU when $\lambda_{S+1}$ is real. AUTO has no guard here: EIGHO 2069-2077 copies the real part into the second column of a complex pair. The guard is the rule of Section 8b for OFS and OFU, and slide 30 assumes real leading eigenvalues.

**First point (design A only).** PREHO starts the adjoint with $\gamma = 0$ and the value 0.1 at every mesh point, and the adjoint phase row of the first Newton step uses that guess as $\tilde\varphi$. The post hoc solve of design B does not need a guess.

**Single source or deferred, not used by the code.**

- The orientation index. AUTO's PSIHO with IS = 0 computes $-S_1 S_2 / \sqrt{\|f(u(0))\|^2 \|f(u(1))\|^2 \|\varphi(0)\|^2 \|\varphi(1)\|^2}$ with $S_1 = \langle f(u(1)), \varphi(0)\rangle$ and $S_2 = \langle f(u(0)), \varphi(1)\rangle$, and 0 when the denominator is 0 (PSIHO 1816-1845, FNCSHO 1757-1771). AUTO only prints it, as "Non-orientable" when it is negative, and only at print level 3 or more. Both research reports read this one piece of code. The definition and sign convention of CKS 1996 are unconfirmed.
- The sign rule for right eigenvectors (EIGHO 2104-2126): the largest component of each column is made positive on the first call, and a later call flips a column whose dot product with the same column of the previous call is negative. The state is kept per ITRANS, not per equilibrium. Section 8b already uses this rule for left eigenvectors. For right eigenvectors it rests on the code alone.
- The ascending eigenvalue order that puts $\lambda_S$ at index $n_s$. The headers of EIGHO ("largest first") and PSIHO ("smallest first") disagree with each other, and the sort at 2082-2102 is ascending. Section 8b uses the ascending order.
- HomCont tests 15 and 16 (non-central saddle-node homoclinic orbits). They belong to the IEQUIB = 2 problem, in which the saddle-node point $x_1$ is an unknown and the eigenvalue at index $n_s + 1$ is held at zero (FBHO 484-501), so they are not tests of the saddle homoclinic problem of Section 8b. Slide 35 gives $\psi_{15} = \frac{1}{T}\langle w_1, x(T) - x_0\rangle$ for a different formulation, and the two forms have not been reconciled. Deferred to the IEQUIB = 2 phase.

**Checks done for this section (ours, not from a source).**

1. *Closed-form adjoint at the parameters of Section 8b, test 1* ($a = \tilde\mu = \alpha = \gamma = \mu = 0$, $b = 1$, $c = -2$). The $(x, y)$ part is divergence free, so $\varphi = (\dot y, -\dot x) = (x - \tfrac32 x^2,\ -y)$ with $\varphi_z = 0$ and $\gamma = 0$ solves the adjoint equation. A numpy check on $T = 40$ with 4000 intervals gives an ODE residual of $2.7 \cdot 10^{-5}$, which is the central-difference error of the sampled functions, a boundary direction $(1, -1)$ at $\tau = 0$ and $(1, 1)$ at $\tau = 1$ (orthogonal to the unstable eigenvector $(1, 1, 0)$ and to the stable space spanned by $(1, -1, 0)$ and $e_z$), and a relative misalignment of $5.8 \cdot 10^{-9}$, which is of the order $e^{-T/2}$. This is the oracle for the residual map. For the flip tests it gives only a limit: the orbit ends are $x(\pm T/2) \approx 4 e^{-T/2}$, so $\varphi(0) \approx x\,(1, -1, 0)$ and $\varphi(1) \approx x\,(1, 1, 0)$, and $|\mathrm{IFS}|$ and $|\mathrm{IFU}|$ tend to $4\sqrt{2}$ as $T$ grows. This is a generic point of the curve, not a flip.
2. *IFS in the models of Section 8b, tests 2 and 3, is at the noise floor.* The $(x, y)$ equations do not depend on $z$, so $f_x$ is block lower triangular and $\varphi_z' = -T C^\top \varphi_z + T\gamma f_z$ with $C$ the $z$ block. The right eigenvectors of $\lambda_S$ lie in the $z$ block, and the stable subspace of $A$ contains the whole $z$ block, so the boundary row at $\tau = 1$ forces $\varphi_z(1) = 0$. With $\gamma = 0$ the equation then gives $\varphi_z \equiv 0$, and IFS is zero for every parameter value on the curve. On the truncated interval $\gamma$ is of the order $e^{-T}$ and so is IFS. A locator that looks for sign changes of IFS on these curves would report labels that mean nothing. Whether to add a guard, and what it should be, is an owner decision.

## 8c. Characteristic roots of linear delay equations (phase E9a, step 1)

Step 1 of E9a finds the characteristic roots of
$$\dot x(t) = A_0 x(t) + \sum_{j=1}^m A_j x(t - \tau_j),\qquad x \in \mathbb{R}^d,$$
with real $d \times d$ matrices $A_j$ and delays $\tau_j > 0$. Write $\tau_{\max} = \max_j \tau_j$. This step reads no `.ode` file and changes no parser, IR or JIT code. The `.ode` syntax for delays, equilibria and their stability in a nonlinear delay equation, Hopf detection, continuation of a delay equation and the normal forms of Bosschaert et al. are later steps of E9a. Neutral equations, distributed delays and state-dependent delays are out of scope.

**Characteristic equation.** $\lambda \in \mathbb{C}$ is a root exactly when $\det\Delta(\lambda) = 0$, with
$$\Delta(\lambda) = \lambda I - A_0 - \sum_{j=1}^m A_j e^{-\lambda\tau_j},\qquad \Delta'(\lambda) = I + \sum_{j=1}^m \tau_j A_j e^{-\lambda\tau_j}.$$
The equation is of retarded type, so only finitely many roots have $\operatorname{Re}\lambda \ge r$ for any $r$. Such a root is an eigenvalue of $A_0 + \sum_j A_j e^{-\lambda\tau_j}$, hence $|\lambda| \le \|A_0\| + \sum_j \|A_j\| e^{-r\tau_j}$ in any induced norm. The tests use this bound to choose a contour that holds every root with $\operatorname{Re}\lambda \ge r$.

**Pseudospectral matrix.** The nodes are $\theta_k = \tfrac{\tau_{\max}}{2}(\cos(k\pi/n) - 1)$ for $k = 0, \dots, n$, the Chebyshev extreme points mapped to $[-\tau_{\max}, 0]$, with $\theta_0 = 0$ and $\theta_n = -\tau_{\max}$ set exactly. $\ell_k$ is the Lagrange polynomial of degree $n$ with $\ell_k(\theta_i) = \delta_{ik}$ and $D_{ik} = \ell_k'(\theta_i)$. The vector $u = (u_0, \dots, u_n) \in \mathbb{R}^{d(n+1)}$ stands for the samples $x(t + \theta_k)$ of the history, and $u_k' = \sum_i D_{ki} u_i$ for $k \ge 1$ replaces the shift. The $d(n+1)$-square matrix $A_n$ has the blocks
$$(A_n)_{0k} = \delta_{k0} A_0 + \sum_{j=1}^m \ell_k(-\tau_j) A_j,\qquad (A_n)_{ik} = D_{ik} I_d\quad (i \ge 1).$$
The eigenvalues of $A_n$ approximate the roots with $|\operatorname{Im}\lambda|$ and $|\lambda|$ small against $n/\tau_{\max}$. Breda, Maset and Vermiglio (2005) introduced this construction for several discrete delays; I read only the bibliographic record of that paper. de Wolff, Scarabel, Verduyn Lunel and Diekmann (arXiv:2006.13810, read) write it for the scalar equation with one delay in the form $\Delta_n(\lambda) = \lambda - L(\ell_0 + P(D - \lambda I)^{-1}D\mathbf{1})$ and show that $\Delta_n \to \Delta$ on every compact set with an error of at most $n^{-1/2}(C/n)^n$ (their Lemma 5.1), so by Hurwitz's theorem the roots of $\Delta_n$ converge to those of $\Delta$ there. The block form above for $d > 1$ and $m > 1$ is my own generalization of that scalar form, and the tests below check it with exact residuals and root counts, not with a citation.

The barycentric form gives $D$ and $\ell_k$ without solving for the interpolant. With $w_k = (-1)^k$, halved at $k = 0$ and $k = n$, $D_{ik} = \frac{w_k/w_i}{\theta_i - \theta_k}$ for $i \ne k$ and $D_{ii} = -\sum_{k \ne i} D_{ik}$. For $s$ that is not a node, $\ell_k(s) = \frac{w_k/(s - \theta_k)}{\sum_i w_i/(s - \theta_i)}$, and $\ell_k(s) = \delta_{ki}$ when $s = \theta_i$ (Berrut and Trefethen 2004). A delay $\tau_j = \tau_{\max}$ always lands on the node $\theta_n$, and a delay can also land on an interior node, so the second case is part of the code and of the tests. Tests 1 and 2 check the formulas by polynomial exactness and against the weights of the product formula.

**Refinement.** Every eigenvalue $\lambda_0$ of $A_n$ with $\operatorname{Re}\lambda_0 \ge r_{\min} - 10^{-6}(1 + |r_{\min}|)$ and $\operatorname{Im}\lambda_0 \ge 0$ is the start of a Newton iteration for $(v, \lambda) \in \mathbb{C}^d \times \mathbb{C}$ on
$$F(v, \lambda) = \begin{pmatrix}\Delta(\lambda)v\\ c^{H}v - 1\end{pmatrix} = 0,\qquad J = \begin{pmatrix}\Delta(\lambda) & \Delta'(\lambda)v\\ c^{H} & 0\end{pmatrix}.$$
This is my own derivation. $J$ is nonsingular when $\lambda$ is a simple root, meaning $w^{H}\Delta'(\lambda)v \ne 0$ for a left null vector $w$ of $\Delta(\lambda)$, and $c^{H}v \ne 0$. The step is solved as a real system of order $2(d+1)$ with the LU of `pc-linalg`. The start vector comes from two steps of inverse iteration on $\Delta(\lambda_0 + \delta)$ with $\delta = 10^{-8}(1 + |\lambda_0|)$ and the right-hand side $b_i = 1 + i/(d+1)$, and $c = v_0/(v_0^{H}v_0)$ stays fixed. The scaled residual is
$$\rho = \frac{\|\Delta(\lambda)v\|_2}{\|v\|_2\, s(\lambda)},\qquad s(\lambda) = |\lambda| + \|A_0\|_F + \sum_j \|A_j\|_F\, e^{-\operatorname{Re}\lambda\,\tau_j}.$$
The iteration stops when $|\delta\lambda| \le 10^{-13}(1 + |\lambda|)$ or after 30 steps, and the root is accepted when $\rho \le 10^{-12}$ and $\operatorname{Re}\lambda \ge r_{\min}$. It is not accepted when the LU reports $J$ singular, when an iterate is not finite, or when $\rho$ stays above the bound. An eigenvalue of $A_n$ with $\operatorname{Re}\lambda_0 \ge r_{\min}$ that does not give an accepted root goes into a second list, `unrefined`, with its $A_n$ value, and with its conjugate when $\operatorname{Im}\lambda_0 > 0$. Nothing in that range is dropped without a record.

The problem is real, so an accepted root with $\operatorname{Im}\lambda > 0$ is returned with its exact conjugate. A start with $\operatorname{Im}\lambda_0 = 0$ stays on the real axis, since $\Delta$ is real there and every operation of the iteration then has a zero imaginary part exactly. Accepted roots that agree within $10^{-11}(1 + |\lambda|)$ are one root, because two eigenvalues of $A_n$ can refine to the same simple root. The result is sorted by real part descending, then imaginary part descending.

**Limits stated up front.** The run does not detect multiplicity. A root of multiplicity $k$ shows up as up to $k$ entries that each have an error near $\varepsilon^{1/k}$, or in `unrefined` when $J$ is singular. `n` fixes which roots can be found. A refined root is a root to the residual bound whatever $n$ is, but a root that no eigenvalue of $A_n$ approximates is missing without a message. The strip $\operatorname{Re}\lambda \ge r_{\min}$ holds roots with $|\operatorname{Im}\lambda|$ up to $B_r$ (test 7), and $A_n$ resolves only the modes with $|\operatorname{Im}\lambda|$ below about $n\pi/\tau_{\max}$, so $n$ has to grow with $B_r\tau_{\max}/\pi$ as $r_{\min}$ falls. Test 7b shows a run that returns a subset of the roots, each with a residual below $10^{-12}$ and an empty `unrefined`. Comparing runs at $n$ and $2n$, or the argument-principle count of test 7, is how a user checks completeness. The input has no default for `n` or `r_min`.

**Input rules.** $d \ge 1$, each matrix has $d^2$ finite entries, there is at least one delay, every $\tau_j$ is finite and positive, $n \ge 1$, $d(n+1) \le 4000$, and $r_{\min}$ is finite. Anything else is `BadProblem`.

**Command line.** `pc-cli dde-roots <problem.json>` reads
```json
{"dim": 2, "a0": [..d*d row-major..], "delays": [{"tau": 1.0, "a": [..d*d..]}], "n": 30, "re_min": -2.0}
```
and prints `{"n", "roots": [{"re", "im", "residual"}], "unrefined": [{"re", "im"}]}`. The reader is strict: a key it does not take is an error. Exit codes follow `cont`.

**Acceptance tests.** All are Rust tests with closed forms or an independent count.

1. Nodes and $D$: $\theta_0 = 0$ and $\theta_n = -\tau_{\max}$ exactly; each row of $D$ sums to 0; $D$ is exact on $\theta^p$ for $p \le n$, $n \le 12$ and $\tau_{\max} = 2$, within $10^{-9}\max|p'|$ (Chebyshev differentiation loses a factor of order $n^2$ in rounding); $D$ built from the product-formula weights equals $D$ from the closed-form weights for $n = 5$ to $10^{-12}$ relative.
2. $\ell_k$: $\sum_k \ell_k(s) = 1$ and $\sum_k \ell_k(s)\theta_k^p = s^p$ for $p \le n$ at nodes and off nodes.
3. $\dot x = -\tfrac{\pi}{2}x(t-1)$: $\pm i\pi/2$ are roots within $10^{-12}$, the largest real part over all returned roots is $0$ within $10^{-12}$, and every returned root has $\rho \le 10^{-12}$.
4. $\dot x = a x(t-1)$ with $a = 1$: the real root is $W_0(1) = 0.5671432904097838\ldots$ (the omega constant) to $10^{-14}$, the largest real part of all roots. With $a = -0.1$ the root nearest zero is a real root of $\lambda = a e^{-\lambda}$ checked by the scalar residual.
5. Rotation system, $A_1 = \begin{pmatrix}a & -b\\ b & a\end{pmatrix}$, $A_0 = 0$: $A_1$ acts on $\mathbb{R}^2$ as the complex number $\mu = a + ib$, so the roots are those of $\lambda = \mu e^{-\lambda\tau}$ and of its conjugate. Every returned root satisfies one of them to $10^{-12}$, and the count with $\operatorname{Re}\lambda \ge r$ equals the argument-principle count of test 7. The commuting pair $A_0 = \begin{pmatrix}p & -q\\ q & p\end{pmatrix}$, $A_1$ as above gives $\lambda = (p + iq) + (a + ib)e^{-\lambda\tau}$ and its conjugate.
6. Two delays, scalar: $\dot x = a x(t - \tau_1) + b x(t - \tau_2)$ with $\tau_2 = 2\tau_1$. The larger delay is the node $\theta_n$. The smaller one is the interior node $\theta_{n/2}$ for even $n$ and lies between nodes for odd $n$, and the test runs $n = 20$ and $n = 21$. Every returned root satisfies $\lambda = a e^{-\lambda\tau_1} + b e^{-\lambda\tau_2}$ with $\rho \le 10^{-12}$ measured by the scalar residual, and the two runs return the same roots to $10^{-11}$.
7. Completeness: for $d = 2$ and $d = 3$ systems with non-commuting matrices, the number of returned roots with $\operatorname{Re}\lambda \ge r$ equals the number of zeros of $\det\Delta$ inside the rectangle $[r, B_r] \times [-B_r, B_r]$, counted as the winding number of $\det\Delta$ along the boundary. Here $B_r$ is the Frobenius bound $\|A_0\|_F + \sum_j \|A_j\|_F e^{-r\tau_j}$ plus 1, which bounds the spectral one. The test computes the determinant with its own complex LU. It samples each edge on a uniform grid of spacing at most 0.01 and then bisects until each phase increment is below $\pi/4$. A single segment per edge aliases, because a whole number of turns gives a phase ratio near 1. The test fails when $|\det\Delta| \le 10^{-8}$ on the contour or when the winding is not near an integer. `unrefined` is empty and every residual is at most $10^{-12}$. The $d = 2$ system with delays 1.0 and 1.7 runs at $r = -2$, $n = 80$ and has 18 roots. The $d = 3$ system with one delay of 1.3 runs at $r = -2.5$, $n = 100$ and has 30 roots.
7b. Small $n$: the $d = 2$ system of test 7 at $r = -3$ has 76 roots by the winding number. $n = 40$ returns 50 of them, and $n = 80$ and $n = 120$ return all 76. Every run has residuals below $10^{-12}$ and an empty `unrefined`. At $r = -2$ the count is 18 for every $n$ from 40 to 200.
8. Errors: a matrix of the wrong length, no delay, $\tau \le 0$, NaN in a matrix, $n = 0$, $d(n+1) > 4000$ and a NaN $r_{\min}$ each give `BadProblem`.
9. `pc-cli dde-roots` on the data of test 3 prints roots with the same values; a missing `n`, an unknown key and an unreadable file exit with the `cont` codes.

## 8d. `.ode` delays, equilibria and their stability (phase E9a, step 2)

Step 2 lets a `.ode` file call `delay(x,tau)`, finds the equilibria of the resulting delay equation and reports the characteristic roots at an equilibrium with the code of Section 8c. It does not simulate a delay equation, continue one, detect a Hopf point on a branch, or compute normal forms. Those are later steps. `lower` and `build` keep refusing every model that calls `delay`, with the error they give today (`IrErrorKind::Delay`), so simulation, continuation, ensembles, code generation, the C ABI and the MATLAB API see no change. The only ways in are `lower_dde`, `build_dde` and `pc-cli dde-eq`.

**What is not verified.** XPPAUT also reads `@ delay=<max>` and takes the history before $t = 0$ from the initial values. PhaseCont reads neither: an equilibrium and its roots need no history, and the option is not used. I did not check what XPPAUT does with `delay(x,tau)` when `x` is not a state, or when `tau` is an expression, so those forms are refused and not guessed at.

**Accepted form.** `delay(x,tau)` may stand wherever a state may in the right side of a state equation, an `aux` formula, a fixed quantity or a user function body, with
- `x` a bare state name, not shadowed by a formal argument of the enclosing user function, and
- `tau` a positive numeric literal, a `number` constant, or a bare name declared with `par`.

Anything else is an error at the call (`IrErrorKind::Delay`, message "the first argument of delay must be a state" or "the delay time must be a number or a parameter"): another first argument, any expression for `tau`, a non-positive literal, a derived parameter or a fixed quantity used as `tau`, a wrong argument count, and a delay in a model with difference equations. `pc-ode` does not check the form. It keeps its ODE0054 warning on every call of `delay`, and the text now says that `delay` is read only by `pc-cli dde-eq` and that simulation and continuation do not support it. `lower_dde` makes every check above, and it also refuses a delay in a table, in the formula of a derived parameter and in a model with difference equations. A parameter value that is not finite and positive when the delays are read is `BadProblem`.

**Lowering.** `lower_dde` is `lower` with the delay refusal replaced by the rules below, and it needs at least one delay call. Each distinct pair (state $k$, delay time) found in the model becomes one hidden parameter, appended after the declared parameters, so that `n_p` counts it, `p` has length `n_p + 1` as before and the last slot is still `t`. The pair is keyed by the state and by the literal value or the parameter, so `delay(x,tau)` twice is one slot, `delay(x,1)` and `delay(x,tau)` are two slots even when `tau = 1`, and `delay(x,1)` and `delay(x,1.0)` are one. A `number` constant is keyed and named by its value, so it shares a slot with the literal of that value. Slots are numbered in the order of first occurrence in the statements of the expanded model. The hidden parameter is named by the call as written with the literal printed by Rust's `{}`, for example `delay(y,tau)` or `delay(x,1)`; no declaration can have such a name. Its entry in `par_values` is NaN, so an evaluation that forgets to set it gives NaN and not a plausible number. `IrModel` gets `n_user_params` and a `delays: Vec<DelaySlot>` with the state index and the delay time (a literal or a parameter index) of each slot. The JIT, the AOT C code, the entry kinds, the C ABI and the `Interp` walk see an ordinary parameter vector. `Interp` reads the slot of a call from the same table.

**Linearization.** Let $G(x, p) = f(x, \ell(x), p)$, where $\ell$ puts $x_k$ into the slot of every pair $(k, \cdot)$, and let the distinct delay times be $\tau_1 < \dots < \tau_m$ (slots of equal value are merged, whether they came from a literal or a parameter). With $J_u$ and $J_p$ the `JacU` and `JacP` entries of the lowered model at $(x, \ell(x), p)$,
$$A_0 = J_u,\qquad (A_j)_{\cdot k} = \sum_{s:\ \text{state}(s) = k,\ \tau(s) = \tau_j} (J_p)_{\cdot s},\qquad \frac{\partial G}{\partial x} = A_0 + \sum_j A_j.$$
At an equilibrium $x(t - \tau) = x^\ast$, so the derivative of $f$ with respect to a delay time vanishes there ($f$ depends on $\tau$ only through $x'(t-\tau) = 0$), and $\tau$ enters the characteristic equation only through $e^{-\lambda\tau_j}$ of Section 8c. This is why a delay time held as a plain parameter is enough, and why the same derivation does not carry over to periodic orbits.

**Equilibria.** $G(x^\ast, p) = 0$ by Newton's method with $\partial G/\partial x$ above, one LU per step, the tolerances and iteration cap of the corrector (`Options`), and `NewtonFailed` otherwise. The routine is `dde::equilibrium(model, setup, opts)`. The caller gives $p$ for the declared parameters only; the routine fills the slots.

**Stability.** `dde::residual(model, x, p)` (exported as `dde_residual`) returns the largest entry of $|f(x, x, p)|$ and is NaN when any entry is NaN; `pc-cli dde-eq` prints it so that a caller sees how well $x$ solves the equation. `dde::stability(model, x, p, root_options)` linearizes at $x$ and calls `characteristic_roots` with $A_0$ and the $(\tau_j, A_j)$. It needs at least one delay time: a model with delays always has one. It does not check that $x$ is an equilibrium. The roots with $\operatorname{Re}\lambda \ge r_{\min}$ are returned with the limits of Section 8c, and `n` and `r_min` have no default.

**Command line.** `pc-cli dde-eq <problem.json>` reads
```json
{"model": "path.ode", "params": {"r": 1.5, "tau": 1.0}, "x0": [0.8], "n": 30, "re_min": -2.0}
```
with `params` naming declared parameters (any other name is an error; one that is missing keeps the file's value, as `cont` does), runs Newton from `x0`, then the roots there, and prints `{"x", "residual", "delays": [tau_j], "roots": [{"re", "im", "residual"}], "unrefined": [{"re", "im"}]}`. The reader is strict like that of `dde-roots`. Exit codes follow `cont`.

## 8e. Hopf points along a branch of delay equilibria (phase E9a, step 3)

Step 3 continues an equilibrium of a delay equation in one declared parameter and reports where characteristic roots cross the imaginary axis. A pair that crosses at $\pm i\omega$ is a Hopf point, and one real root that crosses zero comes with a fold or a branch point, which the engine already finds. It does not continue a Hopf point in two parameters, compute a Lyapunov coefficient, follow a periodic orbit, or compute a normal form. It changes no C function and no MATLAB function, so the only ways in are `dde::continue_equilibrium` and `pc-cli dde-branch`.

**What is not verified.** I did not read how DDE-BIFTOOL or Knut locate a Hopf point along a branch. Counting the roots with positive real part at each point and bisecting where the count changes is my own method, built from the definition of a local bifurcation of an equilibrium (a root on the imaginary axis). The tests below check it against closed forms and against an argument-principle count that shares no code with the engine.

**The branch.** The branch is a curve of solutions of the equation of Section 8d, $G(x, p) = f(x, \ell(x), p) = 0$, with the free parameter $\alpha$. The start is the equilibrium that Newton's method finds from `x0` at the starting value of $\alpha$. The continuation is the pseudo-arclength continuation of `continue_ep`, through `EpProblem` on the collapsed model and `palc::continue_branch`. The free parameter is a declared parameter and may be a delay time. $G$ does not depend on a delay time, so a branch in a delay time has constant $x$. A delay time must stay positive, so when the free parameter is a delay time, `Options::bounds` must have a lower bound above 0, and `continue_equilibrium` returns `BadProblem` otherwise. `Options` are those of `continue_ep`, except that
- `detect_h` is off, since the eigenvalues of $\partial G/\partial x$ say nothing about a delay equation, and
- the refinement pass of `continue_ep` is not run. It needs second derivatives (`Dir` entries) that are not defined for a delay equation, and the fold coefficient of the collapsed model is not that of the delay equation. LP and BP points keep the location the step control gives them, which `locate_one` brackets to $10^{-13}$ in arclength, and they carry no coefficient. The `eigenvalues` stored with each point are those of $\partial G/\partial x$ and have no meaning for a delay equation; `dde-branch` does not print them.

**The count.** $N(\alpha)$ is the number of characteristic roots with $\operatorname{Re}\lambda > 0$, from `dde::stability` at $(x, p)$ with `p[free]` set to $\alpha$, with the options `n` and `re_min` of Section 8c. `re_min` must be negative, so that every root with positive real part is searched for, and a `re_min` of 0 or above is `BadProblem`. A root with $\operatorname{Re}\lambda = 0$ exactly does not count. A point is counted when the run ends, once per point. An error in `dde::stability` at any point is returned as the error of the run.

**Crossings.** Let step $k$ run from point $k$ to point $k+1$ with $N_k \ne N_{k+1}$. Write $d = \|x_{k+1} - x_k\|$ and $v = (x_{k+1} - x_k)/d$, where $x$ is the full state $(u, \alpha)$ of the branch, and let $X(h)$ be the solution of $G = 0$ on the hyperplane $v^\top(X - x_k) = h$, found by `palc::correct` from $x_k + hv$ with the corrector tolerances. Then:
1. `lo = 0`, `hi = d`, with the counts $N_k$ and $N_{k+1}$.
2. At $m = (lo + hi)/2$ compute $X(m)$ and $N(m)$. If $N(m) = N(lo)$ then `lo = m`, otherwise `hi = m`. Stop when $hi - lo \le 10^{-12} d$ or after 60 halvings.
3. This gives one crossing, between `lo` and `hi`. If $N(hi) \ne N_{k+1}$, repeat from `hi` to $d$ with the counts $N(hi)$ and $N_{k+1}$. At most 16 crossings are taken from one step, and a warning says so when the cap is hit.

If `correct` fails at a trial, the step gets a warning naming it and no crossing, and the run goes on.

**Classification.** At the end of the bracket, look at the roots at the end with the larger count (`hi` when $N$ grows, `lo` when it falls) and take the one with the smallest positive real part.
- If $|\operatorname{Im}\lambda| > \omega_{\min} = 10^{-8}$, the crossing is a Hopf point, labelled `H`, with $\omega = |\operatorname{Im}\lambda|$ and the point at that end. $\omega_{\min}$ is a fixed constant of the method, not an option. A real root has $\operatorname{Im}\lambda$ at rounding level, far below it, but a pair that crosses with $\omega < 10^{-8}$ (a Bogdanov-Takens point) is reported as a real crossing.
- Otherwise a real root crosses zero. It is explained when the engine reported an LP or a BP at the same step (a `SpecialPoint` with `index = k + 1`), and the crossing gets no label of its own. If there is none, the run gets the warning "a real root crosses zero between points k and k+1 and no LP or BP is reported there".

**Limits.**
- A step on which one pair enters the right half-plane and another leaves it has $N_k = N_{k+1}$ and is not seen. `hmax` bounds this. Two crossings of different kinds in one step are separated by the bisection only when the count differs at the ends of every sub-interval.
- A subset of the roots is returned when `n` is too small (Section 8c), and the count is then too low without any message. A point of the branch or a bisection trial whose root set has candidates that did not converge (`unrefined`) is reported once per run, as one warning with the number of such points and the first one.
- Several roots on the axis at once (a codimension-2 point) are classified by the one with the smallest positive real part and the rest are not looked at.
- The first Lyapunov coefficient is not computed, so a Hopf point is not called sub- or supercritical.

**Engine API.** `dde::continue_equilibrium(model, setup, roots, opts, cancel)` takes the `&mut DdeModel`, an `EpSetup` as in `continue_ep` (`params` holds the user parameters only, and `free` indexes them), the `RootOptions` of Section 8c and the `Options` above. It returns `DdeBranch { points, specials, stop, warnings }`. A point is `{alpha, x, unstable}`. A special is `{label, alpha, x, omega, between, unstable_before, unstable_after}`, with `label` one of `"H"`, `"LP"` and `"BP"`, `omega` an `Option<f64>`, and `between` the indices of the two points that bracket the step. The bisection is the private function `bisect_crossings(trial, d, n_lo, n_hi)`, where `trial(h)` returns the count at $X(h)$ or `None` when `correct` fails. It returns the brackets plus two flags, `capped` and `failed_at`, and the outer function turns the flags into warnings that name the step. A test can drive it with a made-up count.

**Command line.** `pc-cli dde-branch <problem.json>` reads
```json

```
with `params` as in `dde-eq`. `free` is the name of a declared parameter, and the run starts at its value in `params` or, when `params` does not give it, in the model file. When `free` is a delay time, `options.bounds` must give a lower bound above 0. `options` takes the keys of the `cont` problem files (`h0`, `hmin`, `hmax`, `max_steps`, `tol_x`, `tol_f`, `max_newton`, `direction`, `bounds`, `detect.lp`, `detect.bp`) through the same reader; `detect.h` and `mesh_adapt` are `BadProblem`, since Hopf points come from the count and there is no mesh. `n`, `re_min` and `options` have no defaults except those of `Options`. The output is

```json
               "between": [20, 21], "unstable_before": 0, "unstable_after": 2}],
```

Specials are sorted along the branch, by step and then by distance from the start of the step. `omega` is `null` for LP and BP, and for those `unstable_before` and `unstable_after` are the counts at the two ends of their step. ## 9. Acceptance tests

Exact tests (no oracle needed):

1. **Fold normal form** $\dot x = \alpha + x^2$: LP at $(x,\alpha) = (0,0)$ within $10^{-10}$, and $a = 1$.
2. **Hopf normal form in real coordinates**, with $c = \pm 1$:
$$\dot x = \alpha x - y + c\,x(x^2+y^2), \qquad \dot y = x + \alpha y + c\,y(x^2+y^2).$$
   - The Hopf point is at $\alpha = 0$ with $\omega = 1$.
   - With $\langle q,q\rangle = 1$, the formula gives $l_1 = 2c$. With that normalization $|x|^2 = 2|z|^2$, so the complex coefficient doubles.
   - The sign of $l_1$ must match the sign of $c$.
3. **Hopf normal form limit cycle**, $c = -1$, $\alpha = 0.5$:
   - radius $\sqrt{\alpha}$ within $10^{-10}$ at $N = 40$, $m = 4$
   - period $2\pi$ within $10^{-10}$
   - nontrivial Floquet multiplier $e^{-4\pi\alpha}$ within $10^{-8}$
4. **Collocation convergence** on test 3: the mesh-point error must scale like $O(N^{-2m})$, with the observed order within 0.5 of $2m$ for $m = 2, 3, 4$.
5. **Lorenz**, $\sigma = 10$, $b = 8/3$ (set to `8.0/3.0` exactly, not a rounded literal such as `2.6666667`, which moves the Hopf value by about $2 \cdot 10^{-7}$):
   - BP of the origin at $r = 1$ within $10^{-10}$
   - switching at that BP gives the nontrivial branch, whose points satisfy $x = y$ and $z = x^2/b$
   - Hopf on the nontrivial equilibria at $r = \sigma(\sigma+b+3)/(\sigma-b-1) = 470/19$, within $10^{-9}$
   - $l_1 > 0$ there (subcritical)
6. **Brusselator** $\dot x = a - (b+1)x + x^2 y$, $\dot y = bx - x^2 y$: the equilibrium $(a, b/a)$ has its Hopf point at $b = 1 + a^2$ with $\omega = a$, within $10^{-9}$.
7. **Cusp normal form** $\dot x = \beta_1 + \beta_2 x - x^3$: the LP curve in $(\beta_1,\beta_2)$ passes through a CP at the origin.
8. **Bogdanov-Takens normal form** $\dot x = y$, $\dot y = \beta_1 + \beta_2 y + x^2 + s\,xy$ with $s = \pm 1$: the LP and H curves meet at a BT point at the origin.
9. **Bautin normal form**, in real coordinates of $\dot z = (\beta_1 + i)z + \beta_2 z|z|^2 + s\,z|z|^4$: the H curve has a GH point at $\beta = (0,0)$, and the second Lyapunov coefficient has the sign of $s$.

Oracle tests compare against `references/*.json`:
- **Models:** Morris-Lecar (type I and type II parameter sets), FitzHugh-Nagumo, Hodgkin-Huxley and Rössler (PD cascade).
- **Generating references:** the developer produces them locally with AUTO-07p or MatCont. Each file records the tool, its version and the settings used.
- **Tolerance:** special-point parameter values must agree to $10^{-6}$ relative.
- **Missing references:** a test without its reference file is skipped and reported as "oracle missing", not failed.

FFI tests:
- Calling `pckern("panic")` raises a MATLAB error with ID `phasecont:engine:panic`, and MATLAB keeps running.
- Freed or unknown handles raise `phasecont:engine:badHandle`.
- `pc-cli` runs clean under AddressSanitizer on Linux CI. The job uses a nightly Rust toolchain on GitHub's Ubuntu runner with `-Zsanitizer=address -Zbuild-std`, because Fedora's packaged rustc has no sanitizer runtime.

Performance:
- `pc-cli bench` reports time per step and Newton iterations per step for each model, written to `benches/RESULTS.md`.
- If the developer has CL_MatCont installed locally, compare against it. Set targets after the first phase E5 measurement; do not promise numbers before then.

## 10. C ABI and MEX gateway

**Shape of the boundary.** The Rust side is a `cdylib` named `pckern` that exports a single symbol, `pc_api_v1()`. That function returns a struct of function pointers that starts with an ABI version number and the struct's size in bytes. The table is frozen at ABI version 1 from P7a on. Later fields may only be appended, since the gateway already accepts a `struct_size` at least its own.

```c

  uint32_t abi_version;
  uint32_t struct_size;   /* sizeof the table in this build of pckern */
  int32_t (*model_from_ode)(const char* text, size_t len, uint64_t* model, char** diag_json);

                       const double* p, size_t np, double* out, size_t nout);
```

**Import (P10b).** `import(format, bytes, len, opts_json, &result)` turns a model written in another form into `.ode` text, which MATLAB then hands to `model_from_ode`. `format` is `PC_IMPORT_SBML` (1, SBML text in UTF-8) or `PC_IMPORT_MATLAB` (2, the text of `func2str(h)` or of a function file). The importers read text and never run it. SBML takes no options. MATLAB takes the JSON keys `captures` and `params` (lists of `{"name","value"}`), `state_names`, `init` and `title`, all optional, and any other key is badArg. `jsonencode` writes a one-element list as the bare item, so a lone item counts as a list of one. Nothing defaults to 0: a missing initial value, a missing parameter value and an undeclared name are import errors. On success the result is `{"ok":true,"ode":"...","warnings":[...]}`. A model the importer refuses returns `PC_ERR_MODEL` and sets `*result` to `{"ok":false,"error":{"id":"phasecont:import:<kind>","kind":"<kind>","message":"...","line":L,"col":C}}`, with `line` and `col` only when the error has a position. The kinds are `syntax`, `unsupported`, `undeclared`, `missingValue`, `mismatch`, `nameCollision`, `tooLarge`, `noDynamics` and `xml`. The gateway returns that JSON without raising, and the MATLAB caller raises `phasecont:import:<kind>`. Any other code is raised as `phasecont:engine:<kind>`. Input over 17 MiB is badArg. The work runs on an 8 MiB thread under the panic barrier. The readers cap nesting and output size (expression depth 150, 200 000 nodes, MATLAB text 1 MiB, SBML 16 MiB with 1 000 000 XML nodes, `.ode` output 8 MiB), and the XML reader refuses a DTD. Adding `import` grew the table from 128 to 136 bytes and left `abi_version` at 1.

**Ensembles (P9d).** The five `ens_*` members run many trajectories of one model on the CPU or a GPU. They were appended after `import`; they changed nothing before it, and `abi_version` stays 1. The table was then 23 members and 176 bytes; `latex_render` later took it to 24 and 184.
- `ens_devices(&json)` returns `{"backends":[{"backend","state","why"?}],"devices":[{"backend","index","name","driver","fp32","fp64","memory_bytes"}]}`. `state` is `available`, `unavailable` (with `why`) or `not_built`. A missing GPU library changes a state and is never an error. The first call loads the GPU libraries.
- `ens_start(model, job_json, x0, nx, params, np, &ens)` checks the job on the calling thread, then starts one worker. `job_json` takes `backend` (`cpu`, `cuda`, `opencl`, `metal`), `device` (0-based index among the devices of that backend; the only optional key, default 0), `precision` (`single` or `double`), `t0`, `t1`, `method` (`{"type":"rk4","dt":h}` or `{"type":"dp5","rtol":r,"atol":a,"hmax":h|null}`), `output` (`"final"` or `{"samples":[t, ...]}`), `bounds` (a positive number or null), `max_steps` and `params` (`"shared"` or `"per_member"`). Every key but `device` is required and nothing is filled in. `x0` holds the members one after the other, `n` values each. `params` holds one set, or one set per member when `params` is `per_member`. The model handle is cloned, so the run does not depend on it after it starts.
- `ens_poll(ens, &json)` returns `{"state":"running"}` or `{"state":"cancelled"}`, or `{"state":"done","members","n","samples","counts":{"ok","bounds","step_too_small","max_steps","nonfinite"},"label":{"backend","device","driver","precision","single_precision"}}`. A run that failed returns its error code here and from `ens_copy`, which is how a worker panic reaches MATLAB (rule 7).
- `ens_copy(ens, what, buf, buf_len)` copies one array of a finished run. `buf_len` must match exactly. `what` is `PC_ENS_STATES` 0 (member-major, then sample, then state), `PC_ENS_TIMES` 1, `PC_ENS_STATUS` 2, `PC_ENS_T_REACHED` 3, `PC_ENS_ACCEPTED` 4 or `PC_ENS_REJECTED` 5. A status is 0 ok, 1 bounds, 2 stepTooSmall, 3 maxSteps or 4 notFinite.
- `ens_cancel(ens)` sets the flag the worker checks between launches. `free_handle` on a running ensemble cancels it and joins the worker. The CPU backend checks the flag every 65536 steps.
- Launches are sized to about 100 ms. The GPU libraries are loaded at run time. The `pc-cli dll-imports` allow-list rejects `nvcuda`, `nvrtc` and `OpenCL`, so a `pckern.dll` that imported one fails the release check.
- A job that is wrong in any way is badProblem with a message that starts `bad ensemble job: `, and a tolerance that single precision cannot resolve (`rtol < 13 * 2^-23`) is badProblem with a message that starts `tolerance too tight: `. The gateway keeps both under `phasecont:engine:badProblem`, and the MATLAB layer tells them apart by the prefix and raises `phasecont:ensemble:toleranceTooTight` for the second.
- The gateway commands are `pckern("ens_devices")`, `pckern("ens_start", model, jobJson, x0, p)`, `pckern("ens_poll", id)`, `pckern("ens_copy", id, what, count)` and `pckern("ens_cancel", id)`. The first two return text and an id. `ens_copy` returns a `count`-by-1 double.

**LaTeX (P12b).** `latex_render(kind, doc_json, &out_json)` renders one figure or table document to LaTeX text. It was appended after `ens_cancel`; it changed nothing before it, and `abi_version` stays 1. The table is now 24 members and 184 bytes. The call reads no file and writes none: external data comes back as named files in the result, and MATLAB writes them.
- `kind` is `PC_LATEX_PGFPLOTS` 1 or `PC_LATEX_TABLE` 2. `doc_json` is the document that `pc-cli latex` reads (section 13). Any other `kind`, a NULL `doc_json` or `out_json`, and text that is not UTF-8 are badArg. `*out_json` is NULL after a badArg.
- On success the result is `{"ok":true,"tex":"...","data_files":[{"name","content"}]}` and the call returns 0. `data_files` is empty for inline data.
- A document the renderer rejects returns `PC_ERR_BAD_PROBLEM` and sets `*out_json` to `{"ok":false,"error":{"id":"phasecont:latex:<kind>","kind":"<kind>","message":"..."}}`. The kinds are `missingDigits`, `badDigits`, `nonFinite`, `emptySeries`, `emptyTable`, `lengthMismatch`, `badName` and `badInput`. This adds no error code, and `last_error` holds the same message. The gateway returns that JSON without raising, and the MATLAB caller raises `phasecont:latex:<kind>`.
- The gateway command is `pckern("latex", "pgfplots"|"table", docJson)`. It returns the result text.
- `jsonencode` writes a one-element vector as a bare number, and the renderer needs arrays, so the MATLAB layer wraps every vector before it encodes. NaN and Inf encode as `null` and come back as `nonFinite`.

**Time.** `model_compile` accepts a model whose equations use `t`, and `model_info` reports `autonomous: false` for it. `model_rhs` on such a model returns nonAutonomous with the message `the model depends on t; call model_rhs_t`. `model_rhs_t` evaluates `f(x, p, t)` for any model, needs a finite `t` (badArg otherwise), and a model that does not use `t` ignores it. There is no default for `t`. `run_start` and `model_equilibrium` need an autonomous model and return nonAutonomous otherwise. Adding `model_rhs_t` grew the table from 120 to 128 bytes and left `abi_version` at 1.

**`model_info` keys (P7b).** `source_sha256` is the SHA-256 of the exact bytes passed to `model_from_ode`, in lower-case hex, with no newline or encoding change. It comes from an in-repo implementation of FIPS 180-4 (`pc-ffi/src/sha256.rs`) that is tested against the NIST vectors. `options` lists the `@` options of the model as `[{"name":"total","value":"100"},...]`, with lower-case names, values as written, and the last value of a repeated name winning. These are JSON keys, so the table does not change and `abi_version` stays 1.

**Equilibrium without a free parameter (P7b).** `model_equilibrium` solves F(u, p) = 0 by plain Newton and does not need a free parameter, so a model with no parameters runs `phasecont.equilibrium`. Before P7b it raised "parameter index 0 is out of range". Continuation still needs a free parameter: `EpProblem::new` and the start of a continuation run refuse a setup whose `free` index is not below `n_p`.

**`model_compile` keys (P8a).** `opts_json` takes `evaluator` (`jit`, `fallback` or `aot`). With `"emit_c":"<dir>"`, the call writes the model's C text into that folder and returns its path in `model_info` as `c_file`. With `"evaluator":"aot"`, the call also takes `"aot_lib":"<path>"`, the library that `mex` built from that C text. The engine opens it with `libloading` and calls `pc_aot_init` (section 4). These are JSON keys, so the table does not change and `abi_version` stays 1.

**Error codes.** 0 ok, 1 panic, 2 badArg, 3 badHandle, 4 internal, 5 model, 6 badProblem, 7 nonAutonomous, 8 numeric (`Singular`, `NewtonFailed`, `StepTooSmall`), 9 gpuUnavailable (no such backend or device, or a missing library), 10 gpuCompile (the device compiler refused the kernel), 11 gpuLaunch (a launch or a copy failed), 12 gpuTimeout (one launch ran past the time limit), 13 unsupportedModel (the model uses something a kernel cannot lower). The gateway alone raises `load` and `unknown`. MATLAB error IDs are `phasecont:engine:<kind>`.

**Runs.**
- `problem_json` is the P3 problem JSON without `u0` and `params`, which come only as buffers: `{"type":"EP","free":"r","start_is_special":false,"options":{...},"switch":"BP1"?}`. On the ABI path a `u0` or `params` key is badProblem. pc-cli keeps accepting both keys. `start_is_special` (new in the shared parser, default false) maps to `EpSetup.start_is_special`. MATLAB sets it when the start Point's label is not `EP`, so a run from an H or BP point does not find its own start again. A special start is not solved for an equilibrium first (the Jacobian is singular at an LP). The engine checks that `u0` solves F = 0 to `tol_f`, takes the tangent from the null vector of `[F_u F_alpha]`, and `Direction` picks its sign. An LP or H start runs. A BP start, where that matrix has rank n-1 (smallest singular value below 1e-8 of the largest), ends with `badProblem` and a message that points to the `Switch` option.
- Curve problems use `{"type":"LP"|"H","free":["a1","a2"],"options":{...}}`, with two distinct parameter names. The state buffer holds the point on the curve, and `u0` and `params` give the start as for an EP run. The row alpha is `a2` (`free[1]`), and `Bounds` bound `a2`. `start_is_special`, `switch` and `detect` are not meaningful for a curve, and the MATLAB layer does not send them. The Hopf-curve `kappa` stays in the engine.
- Cycle problems (P5) use `{"type":"LC","free":"a","ntst":N,"ncol":m,"start":"hopf"|"orbit"|"pd","mesh":[...]?,"options":{...}}`. `ntst` is at least 1, `ncol` is from 2 to 7, and `start` has no default. A `hopf` start takes the equilibrium as the state buffer. `orbit` and `pd` take the orbit at the base points, point-major, followed by the period. `mesh` (the $N_{old}+1$ mesh points of the PD orbit) is required for `pd` and refused otherwise; the old $N$ comes from `mesh` and the old $m$ from the length of the state buffer, so the new `ntst` and `ncol` may differ. `orbit` assumes a uniform mesh. `detect` is refused, since LPC, PD and NS are always tested, and `options.mesh_adapt` is accepted for LC only. A problem whose stride would overflow `usize` is refused when it is parsed. `start_is_special` and `switch` do not apply.
- Curves of cycles (P6) use `{"type":"LPC"|"PD"|"NS","free":["a1","a2"],"ntst":N,"ncol":m,"mesh":[...],"options":{...}}`, with two distinct parameter names. The state buffer holds the orbit of the start point at its base points, point-major, followed by the period, and `params` holds the parameters there. `mesh` is required: the $N_{old}+1$ mesh points of the start, at least two, rising strictly from exactly 0 to exactly 1. The old $N$ comes from `mesh` and the old $m$ from the length of the state buffer, and the start is regridded when they differ from `ntst` and `ncol`. `start` is refused, and so are `detect`, `start_is_special` and `switch`. `options.mesh_adapt` is accepted. The row alpha is `a2`, and `Bounds` bound `a2`.
- Homoclinic curves (P14) use `{"type":"HOM","free":["a1","a2"],"ntst":N,"ncol":m,"start":"orbit"|"cycle","mesh":[...]?,"options":{...}}`, with two distinct parameter names. `start` has no default. The state buffer holds an orbit at its base points, point-major, followed by a time: for `orbit` an orbit near the homoclinic orbit on a uniform mesh followed by the truncation time $T$, and for `cycle` a point of an LC branch followed by its period, which becomes $T$. `mesh` is required for `cycle`, with the same rules as for a curve of cycles, and refused for `orbit`. The engine finds the saddle $x_0$ itself (Section 8b), so the buffer holds no equilibrium. `detect`, `start_is_special` and `switch` are refused, and `options.mesh_adapt` is accepted. The row alpha is `a2`, and `Bounds` bound `a2`.
- Initial value problems (P7b) use `{"type":"IVP","tspan":[t0,t1],"options":{"rtol":1e-8,"atol":1e-10,"max_steps":100000,"hmax":0.5}}`. The state buffer holds the start state `x0` and `params` holds the `n_p` parameters. Time reaches a model that uses `t` as the last entry of `p`, so an IVP run accepts a non-autonomous model, while EP and the curves still refuse one. `tspan` is two finite, different numbers, and `t1 < t0` integrates backward. Every key in `options` is optional. The defaults are `rtol` 1e-8, `atol` 1e-10, `max_steps` 100000 and no cap on the step (`hmax` omitted); `rtol`, `atol` and `hmax` must be positive, `max_steps` a positive integer, and an unknown key is badProblem. `tspan` is refused on every other type, and `free` is refused on IVP (an initial value run has no free parameter). The integrator is the Dormand-Prince 5(4) pair with the first-same-as-last property, the error norm and the starting step of Hairer, Nørsett and Wanner (section 15), and the step size controller with the stabilizing exponent beta = 0.04 as in their `dopri5`. A run has one branch. A row is `[t, x(1..n)]` with stride n + 1, one row for the start and one per accepted step, so the last row sits exactly at `t1` when the run ends with the stop reason `End`. Other stops are `MaxSteps`, `StepTooSmall`, `Cancelled` and `Error` (a non-finite right-hand side). `run_copy` with `what = 0` returns these rows, and an IVP branch has no special points.
- `status_json`: `{"state":"running|done|cancelled","kind":"EP"|"LP"|"H"|"LC"|"LPC"|"PD"|"NS"|"HOM"|"IVP","codim2_labels":[],"n":3,"stride":15,"branches":[{"points":120,"stop":"MaxSteps"|null,"warnings":[...],"specials":[{"label":"H","index":57,"coefficient":0.1,"coefficient2":null,"coefficients":{},"omega":9.6,"normalization":"...","refined":true}]}]}`. `specials` appear once the branch has stopped. `codim2_labels` is empty for EP, `["CP","BT","ZH"]` for LP, `["GH","BT","ZH","HH"]` for H, `["LPC","PD","NS"]` for LC, `["LPPD","LPNS","CPC","R1"]` for LPC, `["LPPD","PDNS","GPD","R2"]` for PD and `["R1","R2","R3","R4","LPNS","PDNS","CH"]` for NS, and `["NSA","BLS","BLU","NSF","NDS","NDU","TLS","TLU","ZES","ZEU","OFS","OFU"]` for HOM. The status of every run of cycles (LC, LPC, PD and NS) and of every HOM run also has `ntst` and `ncol`. `coefficient2` is null when a point has none, and `coefficients` is an object with the named extras (`{}` when there are none).
- An EP run uses stride 3n + 6, with the row layout `[alpha, u(1..n), eig_re(1..n), eig_im(1..n), psi_LP, psi_BP, psi_H, h, newton_iters]`, with NaN for missing values. An LP curve run uses `[a2, x(1..n), a1, eig_re(1..n), eig_im(1..n), codim2(1..3), h, newton_iters]`, stride 3n + 7, and an H curve run uses `[a2, x(1..n), a1, kappa, eig_re(1..n), eig_im(1..n), codim2(1..4), h, newton_iters]`, stride 3n + 9. An LC run uses `[alpha, u(1..n(Nm+1)), T, mesh(1..N+1), mult_re(1..n), mult_im(1..n), psi_LPC, psi_PD, psi_NS, h, newton_iters]`, stride n(Nm + 1) + N + 2n + 8, where `u` is the orbit at the base points $\tau_j + (k/m) h_j$ and then $\tau_N = 1$, point-major. An LPC or PD curve run uses `[a2, u(1..n(Nm+1)), T, a1, mesh(1..N+1), mult_re(1..n), mult_im(1..n), codim2(1..4), h, newton_iters]`, stride n(Nm + 1) + N + 2n + 10, and an NS curve run uses `[a2, u, T, a1, kappa, mesh(1..N+1), mult_re(1..n), mult_im(1..n), codim2(1..7), h, newton_iters]`, stride n(Nm + 1) + N + 2n + 14. A HOM curve run uses `[a2, u(1..n(Nm+1)), T, x0(1..n), a1, mesh(1..N+1), eig_re(1..n), eig_im(1..n), codim2(1..12), h, newton_iters]`, stride n(Nm + 1) + N + 3n + 18, where the eigenvalues are those of $f_x$ at the saddle $x_0$. The caller reads the stride from the status JSON. `run_copy` needs `buf_len` equal to `count * stride`, so a caller with the wrong stride gets badArg, and `buf` may be NULL when `count` is 0. It writes at most `count` rows and returns the number in `rows`. Tangents stay in Rust.
- `run_poll` returns 1 when the worker panicked and the kind code when the run failed, with the message in `last_error`. Cancelled is a state in the JSON.
- `free_handle` on a running run cancels and joins inside the barrier. That blocks the MATLAB thread until the worker sees the flag, between Newton iterations.
- `run_start` gives the run its own clone of the model, so a run does not depend on the Model handle after it starts.

**Threads.** Each Model handle owns a thread with an 8 MiB stack. That thread builds the evaluator (the JIT is not `Send`) and serves `model_rhs` and `model_equilibrium` over a channel. Freeing the handle stops and joins the thread. `model_from_ode` parses on an 8 MiB thread. Input over 16 MiB is badArg. The diagnostics JSON keeps the first 1000 diagnostics plus a count of the rest. The registry is one global mutex over `Arc` entries. No call holds the lock across engine work, and a poisoned lock is recovered, so one panic does not break later calls.

**Gateway.** `mex/pckern_gateway.c` is compiled with `mex -R2018a`. The first command that needs `pckern` loads it from the folder that holds the MEX file: on Windows the gateway finds its own file with `GetModuleHandleExW` and `GetModuleFileNameW` and loads `pckern.dll` by full path with `LoadLibraryExW` and `LOAD_WITH_ALTERED_SEARCH_PATH`, and elsewhere it uses `dlopen`. On Linux and macOS the gateway finds its own path with `dladdr(&mexFunction)` and calls `dlopen` with the full path. The commands are `version`, `model_from_ode`, `model_compile`, `model_info`, `model_rhs`, `model_rhs_batch`, `model_equilibrium`, `run_start`, `run_poll`, `run_copy`, `run_cancel`, `import` and `free`. `import(format, text [, optionsJson])` takes `"sbml"` or `"matlab"` as the format and returns the result JSON. `model_rhs_batch(m, X, p [, t])` takes X as n-by-k, one point per column, and returns the n-by-k right-hand sides. The gateway loops over the columns with `model_rhs` or `model_rhs_t`, so one call serves a direction field or a nullcline grid and the C ABI has no batch entry. The binaries sit side by side: `pckern.<mexext>` plus `pckern.dll`, `libpckern.so` or `libpckern.dylib` in `toolbox/bin/<arch>/`. The gateway then calls `pc_api_v1`, requires `abi_version` to equal its own and `struct_size` to be at least the size of its own table, and dispatches on a command string. A failed load raises `phasecont:engine:load`, and the next call tries again. The gateway never unloads `pckern`, since worker threads may still run its code. Loading the library at runtime keeps the gateway independent of the Rust toolchain (MSVC or MinGW on Windows).

**Data rules.** Metadata and options cross as JSON. Numeric arrays are copied into buffers that MATLAB allocated. Rust never holds a pointer into MATLAB memory after a call returns. MATLAB writes numeric option fields with `sprintf('%.17g')`, not `jsonencode`, since `jsonencode` can drop digits. Rust writes JSON numbers in serde_json's shortest round-trip form, and MATLAB reads them with `jsondecode`.

```matlab
m   = phasecont.Model("lorenz.ode", Evaluator="jit");     % or "fallback"
```

- **Branch plots.** `plot(br)` draws stable runs as solid lines (Tag `pc-stable`), unstable runs as dashed lines (`pc-unstable`), and each special point as a marker (`pc-special`) with a text label (`pc-label`). It uses `newplot`, so `hold on` is respected, and `Parent=ax` draws into an axes without resetting it. `continuation(Plot=true)` ends with this plot.
- **Two-parameter curves.** `continuation(m, pt, Type="LP"|"H", Free=["a1" "a2"], ...)` continues an LP or Hopf curve from an LP or H point `pt` (or from any state Point). `Type` defaults to `"EP"`. `Free` takes two distinct parameter names for a curve, and `Bounds` bound `a2`. `Detect`, `Switch` and `Var` apply to EP only and raise `phasecont:model:badOption` on a curve. The Branch has `Type`, `Free`, `Alpha` (N-by-2, columns `a1` and `a2`), `Codim2` (the codim-2 test values) and `Codim2Labels` (`["CP" "BT" "ZH"]` for LP, `["GH" "BT" "ZH" "HH"]` for H). Special points carry the label of the codim-2 point. `Point.Data` has `coefficient` and `coefficient2` (BT: a and b; ZH: b and c; HH: Re P11 and NaN; GH: l2; CP: the cusp coefficient), plus `values`, a struct of the named extras (ZH: `re_d`, `im_d`, `e`; HH: `re_p12`, `re_p21`, `re_p22`, `omega2`). `Branch.Stable` is false on a curve, since the curve has no stability of its own. `plot(br)` draws a curve in the (a1, a2) plane as one solid line (Tag `pc-curve`) with the special markers and labels as for EP, and `continuation(Plot=true)` grows the same plot.
- **Limit cycles (P5).** `continuation(m, start, Type="LC", Free="a", NTST=N, NCOL=m, ...)` continues periodic orbits. `NTST` and `NCOL` are required for LC, have no default and raise `phasecont:model:badOption` on the other types; LC refuses `Detect` and `Switch`, and `Var` works as for EP. The start is a Hopf point (or any equilibrium Point or state vector, which the engine checks; a state with no complex pair fails the run with `phasecont:engine:badProblem`) or a PD point of an earlier LC branch, which starts the period-doubled branch. Any other cycle Point raises `phasecont:model:badStart`. The Branch has `Period` (N-by-1), `Mesh` (N-by-(NTST+1)), `NTST` and `NCOL`. `U` holds the orbit at the NTST·NCOL+1 base points, point-major. `Eigenvalues` holds the Floquet multipliers and `Tests` the LPC, PD and NS test values. `Stable` is true when every multiplier except the one closest to 1 has modulus below 1. `[t, x] = lc.cycle(i)` returns the base-point times from 0 to the period and the states there, with the last row equal to the first. A PD special point carries `Data.period`, `Data.mesh`, `Data.ntst` and `Data.ncol`. `plot(lc, Var="x")` draws the maximum and minimum of x over the orbit against the parameter, stable solid and unstable dashed, with the y label "max, min x", and `continuation(Plot=true)` grows the maximum while the run goes and ends with the same plot. The engine option `mesh_adapt` is not exposed.
- **Curves of cycles (P6).** `continuation(m, pt, Type="LPC"|"PD"|"NS", Free=["a1" "a2"], ...)` continues a curve of fold, period doubling or Neimark-Sacker points of cycles from a special point `pt` with the same label on an LC branch. `Free` takes two distinct parameter names, and `Bounds` bound `a2`. `NTST` and `NCOL` default to `pt.Data.ntst` and `pt.Data.ncol`, and other values regrid the start orbit. `Detect`, `Switch` and `Var` raise `phasecont:model:badOption`, an unknown name raises `phasecont:model:unknownParameter`, and a start that is not such a Point raises `phasecont:model:badStart`. The Branch has `Alpha` (N-by-2, columns `a1` and `a2`), `Period`, `Mesh`, `NTST` and `NCOL` as for LC, `Kappa` (N-by-1, NS only), `Codim2` and `Codim2Labels` (`["LPPD" "LPNS" "CPC" "R1"]` for LPC, `["LPPD" "PDNS" "GPD" "R2"]` for PD, `["R1" "R2" "R3" "R4" "LPNS" "PDNS" "CH"]` for NS). `Eigenvalues` holds the Floquet multipliers, and `Stable` is false. `br.cycle(i)` works as for LC. Special points carry `Data.period`, `Data.mesh`, `Data.ntst` and `Data.ncol`, plus `Data.kappa` on an NS curve. `plot(br)` draws the curve in the (a1, a2) plane as for an LP or H curve.
- **Homoclinic curves (P14).** `continuation(m, lc, Type="HOM", Index=i, Free=["a1" "a2"], ...)` starts a HOM curve (Section 8b) from point `i` of an LC branch `lc`, with the `"cycle"` start of Section 10. `Index` is required with a Branch start, must be an integer from 1 to the number of points, and is refused for every other start and type (`phasecont:model:badOption`). `NTST` and `NCOL` default to the branch's values, and other values regrid the orbit. `continuation(m, s, Type="HOM", Free=[...], NTST=N, NCOL=m)` starts from an orbit given as a struct `s` with fields `t` (k-by-1, strictly rising, model time), `x` (k-by-n) and `p` (a parameter struct). `NTST` and `NCOL` are required here, and the orbit is resampled onto the uniform mesh with `pchip` and sent with the `"orbit"` start, with $T = t_k - t_1$. A start that is neither raises `phasecont:model:badStart`. `Free` takes two distinct names and `Bounds` bound `a2`. `Detect`, `Switch` and `Var` raise `phasecont:model:badOption`. The Branch has `Alpha`, `Period` (the fixed truncation time $T$), `Mesh`, `NTST`, `NCOL`, `X0` (N-by-n, the saddle at each point), `Codim2` and `Codim2Labels` (`["NSA" "BLS" "BLU" "NSF" "NDS" "NDU" "TLS" "TLU" "ZES" "ZEU" "OFS" "OFU"]`). `Eigenvalues` holds the eigenvalues of $f_x$ at the saddle, not Floquet multipliers, and `Stable` is false. `[t, x] = br.cycle(i)` returns the orbit from 0 to $T$, whose ends lie near `X0(i,:)` and do not close. Special points carry `Data.x0` (n-by-1), `Data.period`, `Data.mesh`, `Data.ntst` and `Data.ncol`. `plot(br)` draws the curve in the (a1, a2) plane as for an LP or H curve.
- **Handle classes.** Only `Model` and the internal `phasecont.internal.Run` own Rust handles, and their `delete` frees the handle. `Branch` is a handle class that holds copied data, and `Point` is a value class. `continuation` blocks and polls about every 50 ms with `drawnow`. It grows the plot when `Plot=true`, and Ctrl+C cancels the run and returns nothing.
- **Time in `rhs`.** `m.rhs(x, p, t)` takes a finite real scalar `t`, else `phasecont:model:badTime`. A model with `Autonomous == false` called without `t` raises `phasecont:model:missingTime`; the toolbox never assumes `t = 0`. A model that does not use `t` accepts `t` and ignores it. `equilibrium` and `continuation` still need an autonomous model and raise `phasecont:engine:nonAutonomous`.
- **P8a additions.** `phasecont.config("Codegen", "aot"|"jit")` selects the code path, and `Model(file, Evaluator="aot")` asks for AOT for one model. `Model.AotInfo` has the fields `Compiler`, `Version`, `Flags` and `Library`. They hold the compiler name, its version, the flags used to build the library and the absolute path of that library. They are empty when the model does not run on AOT.
- **Trajectories (P7b).** `tr = phasecont.simulate(m, x0, [t0 t1], Params=, RelTol=1e-8, AbsTol=1e-10, MaxSteps=100000, Hmax=Inf)` integrates an initial value problem with the IVP run of section 10 and returns a `phasecont.Trajectory` handle. `x0` is a state vector or a `Point`, and `t1 < t0` integrates backward. `Params` is a struct or a vector as for `equilibrium`, and a model that uses `t` is integrated with `t` running from `t0` to `t1`. The defaults are the ones in the call above. `Hmax=Inf` means no cap on the step, so a plot of the rows is as smooth as the steps are short, since the solver has no dense output. The Trajectory has `T` (N-by-1), `X` (N-by-n), `X0`, `TSpan`, `P`, `Stop` (`"End"` when the run reached `t1`), `Warnings` and `Model`, and `plot(tr, Var=[x y])` draws a phase plane (Tag `pc-trajectory`) or, with one name, that state against `t`. A run that stops for another reason (`MaxSteps`, `StepTooSmall` or `Error`) warns with `phasecont:simulate:stoppedEarly` and keeps the steps up to then. Ctrl+C cancels the run and returns nothing. `simulate` refuses `Free` and every other option it does not list.
- **Models from text (P7b).** `m = phasecont.Model.fromSource(text, Name="ml.ode", Evaluator="jit")` builds a model from source text, with `Name` used in diagnostics and in `m.File`, and no file read. `m.SourceSha256` is the hash from `model_info`, and `m.Options` is a struct of the `@` options with lower-case field names and string values. `m.rhs(X, p[, t])` accepts an n-by-k matrix X, one point per column, and returns n-by-k through `model_rhs_batch`; a single point keeps its old behavior.
- **Sessions (P7b).** `s = phasecont.Session(m, {br, lc, tr, eq})` holds a model and the Branch, Trajectory and Point objects that `continuation`, `simulate` and `equilibrium` made on it. `save(s, file)` writes a session file and `phasecont.Session.load(file)` reads one. A load builds the Model again from the stored source, checks the hash (`phasecont:session:hashMismatch`) and rebuilds the items from the stored rows without running anything. An item with no run of its own, such as a Point taken from a Branch, raises `phasecont:session:noRecord`, items from another Model raise `phasecont:session:modelMismatch`, and a file that is not a version 1 session raises `phasecont:session:badFile`, or `phasecont:session:badRecord` when a run in it is damaged. Items from one run, such as the two branches of a `Switch`, are stored once.
- **Replay (P7b).** `r = phasecont.session.replay(file, Tol=1e-8, Evaluator=<recorded>)` runs every stored run again through the same engine calls and returns one struct per run with `Kind`, `Type`, `Rows` (`Stored` and `New`), `Identical`, `MaxRelDiff`, `LabelsMatch`, `StopMatch` and `Pass`. A run passes when its shapes, the positions of NaN and Inf, the point counts, the labels with their indices and the stop reasons agree and `MaxRelDiff`, the largest `|a-b|/max(1,|b|)` over the finite numbers with `a` the new value, is at most `Tol`. `Identical` reports bit-for-bit equality and does not decide the pass. The Rust replay (`pc-cli session replay`) of the full Morris-Lecar diagram is `Identical` on all six runs on the build machine. Other platforms and the other evaluators can differ in the last digits, and an adaptive run can then take another step sequence, so a cross-platform replay can fail the shape check. That has not been tested and STATUS lists it as open.
- **Session JSON v1 (`*.pcsession.json`).** One JSON object with `format` (`"phasecont-session"`), `version` (1), `created` (UTC, ISO 8601), `engine` (`name`, `version`), `platform`, `matlab` (the release), `precision` (`"f64"`), `model` (`name`, the file name only, `source`, `sha256`, `evaluator`), `runs` and `items`. A run has `kind` (`"continuation"`, `"simulate"` or `"equilibrium"`), `problem`, `type`, `free`, `grid`, `n`, `u0` and `p`. A continuation or simulate run also has `status`, `rows` and `specials`, and an equilibrium run has `result` with `u`, `eig_re` and `eig_im`. `problem` and `status` are the exact strings that went to `run_start` and came back from `run_poll` (for an equilibrium, `problem` is the options string that went to `model_equilibrium`), since a JSON parse and print can change digits. Every array of numbers is a block `{"shape":[r,c],"f64le":"<base64>"}` holding the r-by-c matrix as row-major little-endian binary64 in base64 (RFC 4648), so NaN, Inf and -0 survive and MATLAB and Rust read the same bits. `rows` and `specials` hold one block per branch with the shape `[count, stride]`. `items` lists `{"run":i,"branch":j}` pairs, one per saved object, with 1-based indices. `model.source` is hashed as given, with no newline or encoding change, and `.gitattributes` keeps fixtures at LF so they hash the same on every runner.
- **Phase-plane app (P7b).** `app = phasecont.app.PhasePlane(m)` opens a programmatic `uifigure` for a Model with at least two variables, and `PhasePlane("diagram.pcsession.json")` opens a saved session instead. `Visible="off"` builds the same figure hidden. The figure has a `uiaxes`, dropdowns for the two plotted states, a table of the parameters, a table of the other states (the slice) when n > 2, a field for T, Forward, Backward or Both, an Integrate or Equilibrium click mode, check boxes for the direction field and the nullclines, and Clear, Save session and Open session. A click in Integrate mode runs `simulate` from that point, with the other states at their slice values. A click in Equilibrium mode runs `equilibrium` and marks the result filled when every eigenvalue has a negative real part and open otherwise (Tags `pc-equilibrium-stable` and `pc-equilibrium-unstable`). The direction field (Tag `pc-field`) is a normalized quiver on a 20-by-20 grid, and the nullclines (Tag `pc-nullcline`, one line per variable with the name in `UserData`) are the zero contours of the two plotted right-hand sides on a 101-by-101 grid, both through the batch `rhs`. Trajectories use Tag `pc-trajectory` and start markers use `pc-start`. Methods for scripts and tests: `clickAt`, `addTrajectory`, `findEquilibrium`, `setParameter`, `setSlice`, `setAxes`, `setWindow`, `setT`, `setDirection`, `setClickMode`, `showField`, `showNullclines`, `clear`, `saveSession`, `openSession` and `delete`. The choices that change what the user sees:
  - The `@` options `xp` and `yp` name the plotted variables (the first two by default). `xlo`, `xhi`, `ylo` and `yhi` give the view range, and only for the pair the model names; any other pair starts at the start value plus or minus max(1, |value|). `total` gives T. When the model sets no `total`, T stays empty and a click raises `phasecont:app:missingTime`; the app does not pick a T. The grid sizes and the view range affect only the display.
  - The app integrates with Dormand-Prince only, and shows a note when the model sets `meth`, `dt` or `bounds`, which it ignores.
  - It passes `Hmax = |T|/500` so a drawn trajectory is smooth. `simulate` itself keeps `Hmax = Inf`.
  - A model that uses `t` integrates with `t` running from 0 to T (Forward), from 0 to -T (Backward) or both.
  - A change of a parameter removes the trajectories and equilibria, which belong to the old values, and redraws the field and the nullclines. A change of a slice value redraws the field and the nullclines and keeps the runs. Clear removes every item.
  - The equilibrium search, the direction field and the nullclines need an autonomous model and raise `phasecont:app:nonAutonomous` for a model that uses `t`. A click can still integrate such a model.
  - A saved session holds the trajectories and equilibria. Branches from a session opened in the app are kept, saved again and not drawn.
  - Error IDs: `phasecont:app:badSource`, `needTwoStates`, `missingTime`, `nonAutonomous`, `unknownParameter`, `unknownVariable`, `sameAxes`, `badValue` and `badWindow`.
- **Model input routes (P10).** Every route ends as `.ode` text that goes to `Model.fromSource`, so the session hash, the JIT, the AOT path, continuation and the ensemble engine treat all models alike. None of them defaults a value: a missing initial value, parameter value or symbol raises a named error.
  - `Model.fromEquations(text, Params=struct, Init=struct, Name="equations.ode")` takes lines such as `x' = y` or `dy/dt = -x - c*y`, one string or a string array. `Params` and `Init` become `par` and `init` lines after the equations, so a parser diagnostic keeps the line number of `text`. An `init` line in `text` raises `phasecont:model:initInText`. A state without an `Init` entry raises `phasecont:model:missingInit`, and an `Init` name that is not a state raises `phasecont:model:unknownInit`. An undeclared symbol is a parse error with its line and column (`phasecont:engine:model`).
  - `Model.fromTable(States=, Params=, Init=, Aux=, Name="table.ode")` takes tables (`Name` and `Rhs` with an optional `Init` for states, `Name` and `Value` for parameters and initial values, `Name` and `Expr` for aux) or structs, writes the equation text and calls `fromEquations`. A NaN in a table `Init` cell means no value was given. An initial value given in both `States` and `Init` raises `phasecont:model:ambiguousInit`. Table errors are `badTable`, `badName`, `duplicateName`, `badValue` and `missingValue`, all under `phasecont:model:`. Numbers are written with `%.17g` or fewer digits that read back to the same double, and a NaN or Inf raises `badValue`.
  - `Model.fromFunction(h, Init=, Params=, StateNames=, Name="function.ode")` translates the text of a function handle. `pc-import` reads that text and the handle is never called, so only a subset works: arithmetic, indexing and the usual math functions. Loops, `if` and calls it does not know raise `phasecont:import:unsupported` with a position. A numeric vector the handle captured becomes constants. `Params` is a struct whose field order gives `p(1)`, `p(2)` and so on, and `Init` has no default.
  - `Model.fromFile(file, Init=, Params=, StateNames=)` chooses by extension: `.ode` as `Model(file)`, `.xml` and `.sbml` as SBML level 2 or 3, and `.m` as a function file (translated as in `fromFunction`). The three options apply to `.m` only and raise `phasecont:model:badOption` for another extension. An extension it does not list raises `badOption` too.
  - SBML supports species, parameters, compartments, reactions with MathML kinetic laws, rate rules and assignment rules. Events, delays and algebraic rules are refused by name. The reader takes UTF-8, UTF-16 and a declared ISO-8859-1 encoding, and a DTD is refused.
  - Import errors are `phasecont:import:<kind>` with the kinds `syntax`, `unsupported`, `undeclared`, `missingValue`, `mismatch`, `nameCollision`, `tooLarge`, `noDynamics` and `xml`, plus `file` for a file that cannot be read. The engine call is `pckern("import", "sbml"|"matlab", text [, optsJson])` and returns JSON, and the MATLAB side raises the error.
- **Ensembles (P9d).** These calls run many trajectories of one model and label every result with the hardware and precision that made it. A tolerance, a precision and a time span have no defaults.
  - `phasecont.gpuDevices()` returns a table with the columns `Backend`, `Index` (the 0-based `Device` value), `Name`, `Driver`, `Fp32`, `Fp64` and `MemoryMiB` (NaN when the driver does not say). The CPU is a row. `[devices, backends] = phasecont.gpuDevices()` also returns one row per backend with `State` (`available`, `unavailable` or `not_built`) and `Why`. A missing driver changes a state and does not raise.
  - `r = phasecont.ensemble(model, X0, P, tspan, Precision=, Rtol=, Atol=, Backend=, Device=, ...)`. `X0` is n-by-M with one start state per column, and a vector of n values is one member. `P` is an np-by-1 vector (one set for all members), an np-by-M matrix (one set per member), a struct that changes named parameters, or `[]` for the values in the model. `tspan` is `[t0 t1]`, or `[t0 s1 ... t1]` to record the states at the times `s1 ...` too, and the times must increase. `Precision` is `"single"` or `"double"` and has no default (`phasecont:ensemble:missingPrecision`). `Dt` selects fixed-step Runge-Kutta 4. `Rtol` and `Atol` select Dormand-Prince 5(4) with one step size per member, and `Hmax` goes with them. Giving both kinds is `ambiguousMethod`, giving neither is `missingMethod`, and giving only one of `Rtol` and `Atol` is `missingTolerance`. `Backend` is `"auto"` (default), `"cpu"`, `"cuda"`, `"opencl"` or `"metal"`. `"auto"` takes the first of cuda, opencl, metal and cpu that has a device for the precision, and the result says which one ran. `Device` counts from 0 within the backend (default 0) and is an error with `"auto"`. `MaxSteps` (100000), `Hmax` (Inf) and `Bounds` (Inf) default to the limits `simulate` uses. A relative tolerance below 13 times the unit roundoff of the precision raises `phasecont:ensemble:toleranceTooTight` and is never changed.
  - `phasecont.EnsembleResult` holds `Model`, `X0`, `P`, `Times` (S-by-1), `States` (n-by-S-by-M), `Final` (n-by-M, the state at the last output time), `Status` (M-by-1 string: `ok`, `bounds`, `stepTooSmall`, `maxSteps` or `notFinite`), `StatusCode`, `TReached`, `Accepted`, `Rejected`, `Job`, `Members` and `Label`, a struct with `Backend`, `Device`, `Driver`, `Precision` and `SinglePrecision`. A member that stops early is not an error. `stepTooSmall`, `maxSteps` and `notFinite` raise the warning `phasecont:ensemble:memberStopped` once per call, and `bounds` does not warn. Ctrl+C cancels the run, and a run cancelled by other means raises `phasecont:ensemble:cancelled`.
  - `refine(r, idx)` runs the members `idx` again from their start states and parameters, in `f64` on the CPU, with the same method, limits and output times. It returns an `EnsembleResult`. A single-precision result is not a start point for continuation, a normal form or Floquet multipliers until it has been refined (rule 6). An index outside `1:Members` raises `phasecont:ensemble:badIndex`.
  - `phasecont.gpuSelfTest(Precision=, Backend=, Device=)` runs four small ensembles: a rotation by RK4 and a decay by Dormand-Prince, each compared with its closed form, then a repeat of the rotation and a run of its first 8 members, which must equal the first run exactly. `Precision` has no default. It returns a struct with `Backend`, `Device`, `Driver`, `Precision`, `SinglePrecision`, `MaxError`, `Pass` and a `Checks` table (`Name`, `MaxError`, `Tolerance`, `Pass`). The thresholds are 5e-4 and 1e-3 in single precision and 1e-8 and 1e-7 in double. They are the test's own and not a claim about accuracy. A backend or device that does not exist raises `phasecont:engine:gpuUnavailable`, never a pass. `pc-cli gpu selftest` runs the longer tiers, including the comparison with the CPU backend.
  - Ensemble results are not stored in sessions. The model source is.
  - Error IDs: `phasecont:ensemble:missingPrecision`, `badOption`, `missingMethod`, `missingTolerance`, `ambiguousMethod`, `toleranceTooTight`, `badIndex` and `cancelled`; `phasecont:model:badStart`, `badParameter` and `unknownParameter` for start states and parameters; and the engine IDs `gpuUnavailable`, `gpuCompile`, `gpuLaunch`, `gpuTimeout` and `unsupportedModel`.
- **Model editor (P10).** `app = phasecont.app.ModelEditor(Visible="on")` opens a programmatic `uifigure` with the tabs Equations, Table and Source, a diagnostics list, and the buttons Check, Open file, Open in phase plane and Save as `.ode`. Check builds a model from the current tab with `fromEquations`, `fromTable` or `fromSource`. A `phasecont:*` error becomes a diagnostic with its line and column when the parser gave them, or the table row for a table error, and the list shows it. A failed check keeps the last good `Model` and `Source`, which the phase plane and Save use. Other errors are not caught. Open file takes `.ode`, `.xml`, `.sbml` and `.m` (a dialog asks for the initial values of a `.m` file) and fills the Source tab. Import errors from Open file are raised and not turned into diagnostics. Properties (read only): `Model`, `Source`, `Diagnostics` (Line, Column, Message, Id), `Tab`, `Status` and `Figure`. Methods for scripts and tests: `setEquations`, `setParameters`, `setInitial`, `setTable`, `setSource`, `selectTab`, `check`, `openFile`, `saveOde`, `openPhasePlane` and `delete`. The app raises `phasecont:app:empty`, `badAssignment` and `noModel`.
- **Apps.** They are programmatic `uifigure` code, not `.mlapp` files.

## 12. Build, CI and packaging

**`buildfile.m` tasks.**
- `cargo`: release build for the current platform. For Windows the allow-list check is `pc-cli dll-imports FILE`, a small PE reader in this repo. The allow-list holds the Windows system DLLs (among them `dbghelp.dll`, which `dlopen2` under `opencl3` imports for symbol lookup), `msvcrt.dll` and `api-ms-win-*`, and the task fails when `pckern.dll` imports anything else. Before a Windows build in WSL it checks that `rustc -vV` and `rpm -q rust-std-static-x86_64-pc-windows-gnu` report the same version, and stops with both versions in the message when they differ. On Windows MATLAB with the repo under `\\wsl.localhost`, the task runs `wsl.exe` to call `scripts/build-pckern win64 <stage>`. With `PHASECONT_PREBUILT` set, it copies prebuilt binaries instead.
- `mex`: build the gateway.
- `test`: run `matlab.unittest` with JUnit output.
- `package`: build the `.mltbx` with `matlab.addons.toolbox.ToolboxOptions`, using a fixed UUID that never changes between versions. Version 1.0.0, set in `buildfile.m`, has `MinimumMatlabRelease` R2026b and ships win64, glnxa64 and maca64. MATLAB R2026b no longer runs on Intel Macs, so there is no maci64 build. `scripts/packageToolbox.m` stages the package in `build/package/PhaseCont/` from `toolbox/`, the binaries in `bin/<arch>/`, the examples, `LICENSE` and `THIRD_PARTY_NOTICES.md`, and fails with `phasecont:package:missingBinary` when a MEX file or library of a listed platform is absent. With `PHASECONT_BINROOT` set to a folder holding `win64/`, `glnxa64/` and `maca64/`, the package covers all three platforms (the release workflow sets it); without it, the package covers the current platform only. With the optional `--overrides DIR`, a crate that ships no license file takes `LICENSE` and `SOURCE` from `DIR/<crate>/`.

**Session replay (P7b).** `pc-cli session replay [--tol X] [--fallback] [--] FILE` reads a `*.pcsession.json` file, rebuilds the model from the stored source, and checks the stored SHA-256 against it. It then reruns every run through the same pckern functions that MATLAB calls: `model_from_ode`, `model_compile`, `run_start`, `run_poll` and `run_copy` for continuations and trajectories, and the Newton entry for equilibria. `--tol` sets the pass rule of §11 (default 1e-8) and `--fallback` evaluates the model with the f64 interpreter in place of the JIT. The command prints a JSON report to stdout with `pass`, `tol`, `engine`, `evaluator` and, for each run, `index`, `kind`, `type`, `pass`, `identical`, `max_rel_diff`, `rows_match`, `labels_match`, `stop_match`, `seconds` and `message`. The exit code is 0 when every run passes, 1 when a run does not match or cannot be rerun, and 2 for an unreadable or unsupported file, a hash mismatch or a usage error. A test in `crates/pc-cli/tests/` builds the full Morris-Lecar diagram, writes a session, and checks that the replay passes with `identical` true on every run; it also checks that a changed row exits 1, and that a changed source and an unknown version exit 2.

## 13. Later phases (pointers only)

- **GPU ensemble engine** (`pc-ensemble`). One thread runs one trajectory. A kernel advances each trajectory by at most K steps and the host relaunches until all are done, with K sized so one launch takes about 100 ms (the Windows watchdog). A GPU speeds up ensembles only: one run and all continuation stay on the CPU in `f64`. Backends:
  - `cpu`: rayon; the reference for every other backend, in both precisions.
  - `cuda`: `cudarc`, driver API plus NVRTC; primary for NVIDIA. Spike S4 compiled and ran an `sm_120` kernel with it on the developer's GPU, inside MATLAB R2026b and in WSL. NVRTC is not bundled, since it is a proprietary NVIDIA binary. The engine looks for it at run time, first MATLAB's own copy and then a CUDA toolkit on the machine. With neither, an NVIDIA GPU runs through `opencl`.
  - `opencl`: the `opencl3` crate with its `dynamic` feature, so the library is loaded at run time and never linked; for AMD, Intel and NVIDIA. AMD and Intel have no other backend. The kernel text writes its single-precision literals with an `f` suffix, and double precision needs `cl_khr_fp64`.
  - `metal`: the `objc2-metal` crate, macOS only, `f32` only (MSL has no `double`). The host code is in `crates/pc-ensemble/src/metal/host.rs` and is built on macOS only. It compiles with fast math off, dispatches whole threadgroups of `GROUP` threads (rounded to a multiple of the pipeline's execution width) and keeps every Objective-C object inside one run. The macOS build is type-checked on Linux with `RUSTC_BOOTSTRAP=1 cargo check -Zbuild-std=std,panic_abort --target aarch64-apple-darwin -p pc-ensemble`, which does not link or run it. Nothing has run on a Mac.
  - There is no `hip` backend. `hiprtc` is not shipped with consumer AMD drivers.
  - Kernels are emitted as text for each dialect (C, CUDA C, OpenCL C, MSL) from one shared body and compiled at runtime. The engine uses `f64` everywhere. `f32` exists only in GPU ensemble screening, and those results are labeled as single precision and recomputed in `f64` before they feed continuation, normal forms or Floquet multipliers.
  - A job has no default precision and no default time span, and a tolerance that single precision cannot resolve (`rtol < 13 * 2^-23`) is an error, not a clamp. Every result carries its backend, device, driver and precision.
  - `cuda` host code calls `is_culib_present` for the driver and NVRTC before any other `cudarc` call, because `cudarc` panics when it cannot load a library. It compiles kernels through the raw NVRTC calls and destroys the program on every path: when a compile fails and reading the program log fails too, `cudarc`'s `compile_ptx_with_opts` panics, and the `Drop` of its program panics again if destroying the program also fails. That second panic aborts the process, which `catch_unwind` cannot stop.
  - NVRTC contracts `a*b + c` into an FMA by default (`--fmad`, "Default: true" in `/usr/local/cuda-13.4/include/nvrtc.h:960-965`). Kernels are compiled with `--fmad=false`, and a test that compares a GPU result with a CPU reference at the level of single ulps rounds each operation once in the reference. It does not get that rounding from `f32::mul_add` on `x86_64-pc-windows-gnu` at the baseline target features.
  - The `cuda` backend (`crates/pc-ensemble/src/cuda.rs`) looks for NVRTC in this order: the bare library name, which inside MATLAB gives MATLAB's copy, then a toolkit named by `CUDA_PATH`, `CUDA_HOME` or `/usr/local/cuda`, loaded by absolute path with its builtins library first. It reads the driver version and the NVRTC version and picks the route from them. When the driver is at least as new as NVRTC, NVRTC emits PTX for `compute_XY` and the driver compiles it. When the driver is older but at least 13.0, NVRTC emits a cubin for `sm_XY`. With any other pair there is no route and the run fails with `gpuUnavailable`. A job is validated before any GPU library is touched, so a bad job fails the same way on every backend.
  - A launch runs at most K steps. K starts at 16, grows at most 4 times per launch toward the 100 ms target, shrinks at once when a launch runs long, and never reaches 0. If no member advanced in a launch while some are still running, the run stops with `gpuLaunch` and does not retry. A driver error 702 (launch timeout) becomes `gpuTimeout`. Every call into `cudarc` is wrapped so that a panic from a missing library or a failed cleanup becomes an error and never crosses the C ABI.
  - The CUDA tests that need no driver (`tests/cuda_compile.rs`) compile four models in four variants (RK4 and Dormand-Prince, `f32` and `f64`) to PTX for `compute_75`, `compute_80`, `compute_90` and `compute_120`, and check that the output is the same on a second compile. A machine without NVRTC prints a `SKIPPED` line. `PC_REQUIRE_GPU=nvrtc` (or `cuda` for a device run) turns that skip into a failure, so a hosted CI job that installs NVRTC cannot pass without compiling.
  - The `opencl` backend (`crates/pc-ensemble/src/opencl.rs`) probes every platform once and lists each device with its fp64 support (`double_fp_config` and the `cl_khr_fp64` extension). A missing OpenCL library, no platform and no device each give `gpuUnavailable` and never a panic: with the `dynamic` feature a missing library returns an error code, and `OPENCL_DYLIB_PATH` names a library to load. Every call into `opencl3` and every drop of its objects is wrapped, because those drops use `expect`. Programs are built with `-cl-std=CL1.2`, never with fast-math, and with `-cl-fp32-correctly-rounded-divide-sqrt` only when the device reports it. The kernel text has `#pragma OPENCL FP_CONTRACT OFF`. Whether a given driver honours that pragma is not checked, and the bit-exact tier of the self-test is what shows it. A buffer above `CL_DEVICE_MAX_MEM_ALLOC_SIZE`, or a total above the device memory, is a `BadJob` before any launch. The global size is rounded up to a whole work group and the kernel guards on the member count. The launch loop is the one `cuda` uses (`gpu.rs`). A `CL_OUT_OF_RESOURCES` that arrives after a launch of at least 1.5 s is reported as `gpuTimeout`, which is a guess about how drivers report a watchdog reset and is unverified.
  - `tests/opencl_compile.rs` checks the OpenCL kernel text for the same four models and four variants with `clang -x cl -cl-std=CL1.2 -fsyntax-only`, with no OpenCL runtime and no device. That shows the text parses as OpenCL C 1.2. It does not show that a driver compiler accepts it. `PC_CLANG` names another clang. A machine without clang prints a `SKIPPED` line, and `PC_REQUIRE_GPU=clang-opencl` turns the skip into a failure.
  - `pc-cli gpu list` prints every backend and device. `pc-cli gpu selftest --backend B --precision P [--device N]` checks closed-form error, determinism and, for a device that is not the CPU, bit-exactness with the CPU backend. It exits 0 on a pass, 1 on a failure and 3 when the backend is not built or the device does not exist, which is never a pass. `pc-cli ensemble MODEL JOB` runs a job file, and `pc-cli ensemble --bench` times it.
- **VS Code extension (P11).** `crates/pc-lsp` is a Rust language server that speaks LSP over stdio, and `editors/vscode/` is a TypeScript client. The server calls `pc_ode::load()` and never parses on its own.
  - It uses `lsp-server` (synchronous, no async runtime) and `lsp-types`. `tower-lsp` was the first choice, but its last release is from 2023-08.
  - `pc-ode` spans are byte offsets and its columns count scalar values, while LSP counts UTF-16 units from 0. A conversion module maps one to the other against the buffer text and clamps an offset that is out of range, because `SourceMap::line_col` panics on one.
  - A diagnostic keeps its code (`ODE0001`) and severity, and `source` is `phasecont`. `notes` become related information, a `FixIt` becomes a code action, and a diagnostic in an included file goes to that file. Documents sync in full. Queued changes to one document are drained so only the last text is loaded, and diagnostics carry the document version.
  - An overlay loader serves unsaved buffers before disk. It resolves `#include` only inside the workspace folders or the document's directory, so opening a model cannot make the server read other files. Anything outside gives an unresolved-include diagnostic.
  - Features: hover (builtin signatures, symbol kinds), completion (builtins, declared names, `@` option names), document symbols, go to definition and code actions. Every handler runs under `catch_unwind`. A panic answers that request with an internal error and the session continues.
  - The client finds the server in a bundled per-platform binary or in the `phasecont.server.path` setting. The TextMate grammar is written from `crates/pc-ode/docs/language.md` and the lexer, not from any XPPAUT-derived grammar. The setting has machine scope and never falls back to the bundled server, so a wrong path is reported. The extension is bundled with `esbuild` into one file. One `.vsix` is built per platform with `@vscode/vsce`, a dev-only build tool that the owner approved as a licence exception on 2026-11-06 (its tree includes the proprietary `@vscode/vsce-sign`; the list is in `docs/STATUS.md`). It never ships inside the `.vsix`. CI builds the linux-x64 `.vsix` and checks its contents. Publishing to the Marketplace is the owner's job.
  - Acceptance: `cargo test -p pc-lsp` passes. It covers a `proptest` round trip of byte offsets through UTF-16 positions over random UTF-8 with astral characters and CRLF, one LSP diagnostic with the right code, message, severity and range for every diagnostic that the files in `crates/pc-ode/tests/invalid/` produce, the overlay and include rules, a stdio session (`initialize`, `didOpen` with an error, `didChange` that clears it, a malformed message that does not end the session, `shutdown` and `exit` with code 0, `exit` without `shutdown` with code 1), 100 queued changes that cause one load, the panic guard on a closure that panics, and one test per feature. In `editors/vscode`, `npx tsc --noEmit` and `node --test` pass, and the grammar tests tokenize a model file as expected. The extension has not run inside VS Code.
- **LaTeX companion (P12).** `crates/pc-latex` turns plain data into LaTeX text and does no I/O. The MATLAB side is `phasecont.latex.*` inside the main toolbox and `phasecont.app.LatexStudio`.
  - The crate takes one JSON document and a kind, `pgfplots` or `table`, and returns the LaTeX text plus any data files. `pgfplots` writes an `axis` with one `\addplot+` per series, solid for stable and dashed for unstable, and a mark and label for each special point. Unnamed series get `forget plot`, so legend entries stay aligned. It writes a fragment for `\input`, or a `standalone` document when the JSON key `standalone` is true. With `data` set to `"inline"` (the default) the points are `coordinates` in the `.tex`. With `"external"` they are `<basename>-s<N>.dat` tables next to it, `basename` is required and must match `[A-Za-z0-9_-]{1,100}`, and the caller must have an output folder. `basename` with inline data is an error. `table` writes a booktabs `tabular` of label, type and one column per coordinate, with numbers as math cells.
  - The reader is strict. A key that no reader takes is an error, so a misspelled option never goes unnoticed. `x`, `y`, `class` (`stable` or `unstable`), `xlabel` and `ylabel` are required. `color` is `#RRGGBB`.
  - `escape` handles `# $ % & _ { } ~ ^ \`. It also escapes `[ ] < > |` (`{[}`, `{]}`, `\textless{}`, `\textgreater{}`, `\textbar{}`) so that label text cannot open an optional argument or print as a different glyph, and it turns control characters into spaces. Axis labels, titles, legend entries and special-point labels always go through `escape`, so a raw math label is not supported. Non-ASCII text passes through unchanged.
  - `digits` has no default. It is an integer from 1 to 17 and counts significant digits, printed like C's `%.{digits}g` with ties to even and exponents without `+` or leading zeros. A missing one is the error `missingDigits` (`phasecont:latex:missingDigits` in MATLAB), and a value outside 1 to 17 is `badDigits`. A non-finite number is the error `nonFinite` that names its series or row and its 1-based index, and is never dropped. `null` counts as non-finite, because MATLAB's `jsonencode` writes `null` for NaN and Inf.
  - The command line is `pc-cli latex pgfplots|table <file.json> [--standalone] [--out <file.tex>]`. Without `--out` the text goes to stdout. With `--out`, external data files are written beside it. Exit code 0 means success, 1 an invalid document, an unreadable or unwritable file, or external data without `--out`, and 2 a usage error. A failed render writes nothing. `--standalone` sets the JSON key of the same name.
  - The compile driver is MATLAB code. It copies the document into a generated temporary folder as `main.tex` and runs `latexmk -pdf -norc -no-shell-escape -interaction=nonstopmode -halt-on-error -file-line-error -output-directory <tmp>`, so no user text reaches the command line. It never enables shell escape. It parses the `-file-line-error` log into line and message pairs. The `Timeout` option limits the run. Its default is `Inf` (no limit), which the owner chose on 2026-11-06 after vetoing 300 s. `latexmk` starts through `java.lang.ProcessBuilder` in the MATLAB JVM for every `Timeout`, and `Inf` only turns the clock off, so Ctrl-C works with the default too. On Windows the program name is looked up on `PATH` with `PATHEXT` first, because Java adds only `.exe` to a bare name, and so a `latexmk.cmd` wrapper starts. The wait loop polls with `pause`, and on expiry or on Ctrl-C it stops `latexmk` and every process it started (`ProcessHandle.descendants`, Java 9 or later). The result has a `TimedOut` field, with `Ok` false and `Pdf` empty. When the JVM cannot start the program, a finite `Timeout` warns with `phasecont:latex:noTimeout` and `build` runs `system` with no limit, and `Inf` takes the same fallback without a warning. Only `latexmk` is supported: Tectonic's flags are not confirmed, so it is left out until a local install lets them be checked. No TeX distribution is bundled.
  - `phasecont.latex.figureFromBranch(br, Var=, Color=, Title=)` returns the figure struct that `pgfplots` renders, with the data of `plot(br)`. An EP branch is one series of `Var` against the free parameter, an LC branch is two series (maximum and minimum of `Var` over each orbit), and a curve (LP, H, LPC, PD, NS) is one series in its parameter plane and takes no `Var`. Runs of equal stability are separate series that share their boundary point. `Color` is one `#RRGGBB` for every series and defaults to black.
  - `phasecont.latex.specialTable(br, Digits=)` has one row per special point. The columns are the free parameters, plus the state variables for EP, LP and H. The row label is the point's label followed by its running number, and the type name comes from a fixed map. A branch with no special points raises `phasecont:latex:emptyTable`. The MATLAB side adds the error ids `phasecont:latex:writeFailed` (a folder or file that cannot be written), `engineNotFound`, `badEngine` (an `Executable` path with characters outside letters, digits, spaces and `_ - . / \ : ( ) + `) and `badInput`.
  - `LatexStudio` has an editor, a Summary pane, an error Context pane and Errors and Log tabs. The preview is the system PDF viewer. Selecting an error shows its context lines with the error line marked with `>`, because the `uitextarea` cursor API is not confirmed here. Insert figure and Insert table always write inline data, and Compile blocks the window. The app raises `phasecont:app:{badOpener,openFailed,saveFailed,empty,noSuchError,noPdf,noBranch}`. A pdf.js preview in a `uihtml` page was in the plan as an option and is not built, since it cannot be tried without MATLAB. `LatexStudio` has no `Preview` option, and `THIRD_PARTY_NOTICES.md` has no pdf.js entry.
  - Acceptance: `cargo test -p pc-latex` and `cargo test -p pc-cli` pass. `pc-latex` covers a `proptest` that `escape` leaves no raw special character outside a backslash command, a `proptest` that 17 digits round-trip a double, golden `.tex` files (stable and unstable series with marks, a table, external data with its `.dat` files), a standalone wrap, the error cases (null, 1e999, empty series and table, missing and bad digits, length mismatch, basename rules, unknown keys), and a compile of every golden file, as a fragment inside an `article` and as a `standalone` document, with the `latexmk` flags above to a PDF. A machine without `latexmk` prints `SKIPPED: no latexmk`, and `PC_REQUIRE_LATEX=1` turns the skip into a failure. `pc-cli` covers the command line cases above, including that a failed render writes no file. The C ABI gains one function, `latex_render`, with a matching gateway command. The MATLAB tests (`tests/LatexTest.m`) check that the API output equals the Rust output for the same figure and that a missing `Digits` raises.
