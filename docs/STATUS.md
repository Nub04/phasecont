- Rulings made while building P9a:
  - A job has a `nonfinite` status in addition to ok, bounds, step_too_small and max_steps. A member whose state becomes NaN or infinite stops and reports it, and the run still succeeds.
  - Time runs forward only (`t0 < t1`). Samples are strictly increasing in (t0, t1] and the last one is `t1`.
  - The RK4 `dt` is a maximum step, and the last step of an interval is shortened to land on it. The Dormand-Prince steps are cut to land on each sample time.
  - The single-precision unit roundoff is 2^-23. A Dormand-Prince `rtol` below `13 * UROUND` for the job precision is `ToleranceTooTight`, an error and not a clamp.
  - A NaN error estimate shrinks the step by 5 until the step-size check fails, and the member then reports `nonfinite`.
  - The ensemble kernels use `libm::pow`, so the CPU backend and the shim agree bit for bit. `emit_c` in `pc-codegen` is not changed.
  - `refine(i)` (P9d) will run member i again through the CPU backend in `f64`.
  - The self-test reports `bit_exact: null` for the CPU backend, because it is the reference. A backend that is not built, or a device index that does not exist, gives exit 3 and nothing on stdout, never a pass. A device that refuses a job gives exit 1.
  - The tier limits of the self-test come from measurements on the CPU backend, with the margins written next to each limit in `selftest.rs`.
  - `gpu selftest` needs `--backend` and `--precision`. `--device` defaults to 0, and the JSON names the device that ran.
  - `ensemble --bench` runs both precisions on every device, labels each row and prints its sizes (1000, 10000 and 100000 members unless `--members` says otherwise). A device without double precision gets a `skipped` row.
  - The job file needs every key except `device`. `bounds` is a positive number, or `null` for no limit. Unknown keys are errors and each error names its key.
  - The self-test JSON has a `commit` field that is the value of `PC_GIT_COMMIT` at build time, or `null`. There is no `build.rs`.

P15, step 1 of E9a: characteristic roots of a linear delay equation (branch `dde-roots`, from `main` at 375d3c4, commits edc3358 to 5ee9362; Rust only, no MATLAB part, no C ABI change, no MATLAB API change, no new dependency).

- Scope: `x' = A0 x + sum_j A_j x(t - tau_j)` with constant matrices and positive delays. `pc-engine` gets a `dde` module (`nodes.rs`, `roots.rs`) with `characteristic_roots`, and `pc-cli` gets `dde-roots problem.json`. SPEC section 8c has the formulation, the JSON layout, the exit codes and tests 1 to 9.
- Method: a pseudospectral matrix of order d(n+1) on Chebyshev extreme nodes of [-tau_max, 0] gives the candidates. Each candidate is refined by Newton on the bordered system [Delta(l) v; c^H v - 1], where Delta(l) = l I - A0 - sum A_j exp(-l tau_j), in a real embedding of order 2(d+1). A root is kept when the scaled residual is at most 1e-12 and Re l is at least `re_min`. A candidate that fails goes to `unrefined`. `n` and `re_min` are required keys with no default.
- Tests: 7 integration tests in `crates/pc-engine/tests/dde_roots.rs`, 5 unit tests in `nodes.rs`, 3 unit tests and 1 usage test in `pc-cli`, and 4 integration tests in `crates/pc-cli/tests/dde_roots.rs`. The root counts are checked against a winding-number count of det Delta on a rectangle (test code only), and they agree: 9 = 9 for the scalar test at n = 20 and n = 21, 4 = 4 and 6 = 6 for test 5, 18 = 18 for d = 2 at r = -2, 30 = 30 for d = 3 at r = -2.5. The largest residual is 6.8e-15. The CLI check x'(t) = -(pi/2) x(t-1) finds the roots at +-i pi/2 to 1e-12.
- Limit, recorded in SPEC section 8c and test 7b: the pseudospectral matrix resolves only modes with |Im l| below about n pi / tau_max. The strip Re l >= `re_min` holds roots up to a height that grows as `re_min` falls, so n must grow with it. A too-small n returns a genuine subset of the roots with small residuals and an empty `unrefined`, so nothing flags the missing roots. Measured on the d = 2 test system with delays 1.0 and 1.7: at `re_min` = -3, n = 40 gives 50 of 76 roots and n = 80 to 200 give 76. The user chooses n, and the winding count is the check.
